# haisou.cc 网盘资源监控 SOP

## 入口
- `birdie_monitor/haisou_daily.py`：搜索、按 `hsid + 标题相似度` 双重去重、仅新增通知。
- `birdie_monitor/sync_quangneng.py`：同步全能IT（quangneng.com）首页最近90天课程到动态关键词。
- 调度定义：`sche_tasks/haisou_daily_monitor.json`（每天11:15，先sync再搜索）。

## 认证
- 会员会话 Cookie `hs_web_session` 是 HttpOnly；通过 keychain 读取，严禁明文落盘或输出。脚本可脱离浏览器运行。

## 核心接口
- `POST https://haisou.cc/api/v2/shares/search`
  - body: `{"query": "关键词", "filters": {"scope": "title", "platforms": ["quark"|"baidu"|"ali"], "include_filtered": false}, "pagination": {"page":1, "page_size":N}}`
  - **必须**在 `filters.platforms` 里显式指定至少一个平台，否则报 `400 INVALID_PARAMETER 至少选择一个云盘`（此为参数校验错误，非认证失效，勿误判会话过期）。
  - 已验证可用平台枚举：`quark`、`baidu`、`ali`（页面渲染观察到的三种图标对应值）。
  - 返回 `data.items` 直接包含 `hsid`、`platform`、`share_name`(含 `<span class="highlight">` 高亮标签需 strip)、`share_code`、`share_pwd`，日常监控无需再调用详情/fetch接口。
- `POST /api/v2/shares/{hsid}/fetch`：返回同样字段但会消耗 5 会员额度/次，仅用于人工核实，不应在定时监控里对每条结果调用。
- 链接生成规则（脚本实际采用，已用浏览器实测校验）：
  - 夸克: `https://pan.quark.cn/s/{share_code}`
  - 百度网盘: `https://pan.baidu.com/s/{share_code}`（`share_pwd` 需要用户自行输入提取码，不能拼进URL）
    - **坑（2026-08-31已修复）**：接口返回的 `share_code` 本身已经带开头的 `1`（如 `1xkDD27op2R2lUvUPTsB_mQ`），旧模板 `s/1{share_code}` 会多拼一个 `1` 导致链接 404。`haisou_daily.py` 的 `LINK_TEMPLATES["baidu"]` 已改为 `https://pan.baidu.com/s/{code}`（无多余前缀），历史 `haisou_seen_items.json` 中218条百度记录已批量修正 link 字段。今后若切回 quark/ali 之外新平台，务必先用浏览器实测生成的链接再定模板，勿凭直觉加前缀。
  - 阿里云盘: `https://www.alipan.com/s/{share_code}`

## 去重与相关性机制
- **双重去重**（2026-09-05 增强）：
  1. **hsid 去重**：同一资源的唯一ID，不同平台同一资源hsid不同
  2. **标题相似度去重**：归一化标题后用 SequenceMatcher 计算相似度，threshold=0.85
     - 归一化规则：转小写、去除"完结/更新中/1080P/高清/4K/蓝光/网盘名"等噪声词、去除括号中内容、去除标点符号
     - 效果：能减少约70%的同课程不同平台重复推送
     - 边界情况：标题差异较大时（如"华测AI测试" vs "华测教育2026年AI全栈测试专家课程"）可能漏过
- **结果-关键词相关性校验**（2026-09-10 根治垃圾推送）：
  - **根因**：`haisou.cc` 标题搜索是 OR 式分词模糊匹配，不是精确短语。宽泛/长标题动态关键词（如“全民AI做漫剧｜…豆包 扣子”“和橘子学AI创作…”）会拆出“全民/和/AI”等高频词，返回大量无关小说/电影/破解资源；脚本原先只做 hsid+标题去重，从不校验结果与关键词本身是否相关。
  - **规则**：入库/通知前调用 `is_relevant(keyword, title)`——按分隔符+中英文边界切词，**要求最长核心词必须作为子串出现在标题中**（例：`AI Agent` 必须命中 `Agent`，不能仅因命中 `AI` 放行）；**实现=单一源 `tools/haisou_relevance.py`（2026-09-27 R441）**。
  - **验证**：对 2026-09-09/10 共 716 条历史样本可拦截约 601 条垃圾，保留约 115 条；6 组正反样本回归通过。
  - **注意**：已污染的 `haisou_seen_items.json` 默认不自动清理（改基线会影响去重）；若需清理由人工确认后批量剔除不相关记录。

## 监控设计
- 首次运行：只建立本地基线（写入 `haisou_seen_items.json`），不对外通知。
- 后续运行：仅当出现新 `hsid`（新增资源）或接口报错/会话失效时才通知(飞书私信+钉钉群各一次)；无新增静默，避免刷屏。
- **部分扫描失败不得吞结果**（2026-09-07 修复并离线验证）：若某些关键词/平台已发现新增、后续请求才遇到额度耗尽或其他异常，必须在**同一条通知**先列出已发现的新增，再附“后续扫描中断”及错误；已发现资源必须立即写入 `haisou_seen_items.json`，未扫描部分留待下次，不能以异常分支覆盖结果或造成重复推送。
- 定时任务流程：
  1. 执行 `sync_quangneng.py`（抓取全能IT首页最近90天课程 → 更新动态关键词）
  2. 执行 `haisou_daily.py`（静态关键词+动态关键词 → 海搜搜索 → 双重去重 → 通知）
- **无人值守运行要点（2026-09-21 实测，2026-09-23 修订）**：两步合计约 1~2 分钟（额度充足时更久），应以后台方式起再用 `pgrep -f haisou_daily.py` 轮询，**不要**用会阻塞的长等待。注意脚本 `print` 有缓冲，日志在进程结束前一直为 0 字节——**判活只能靠进程存在与否，不能看日志有无内容**；加 `-u` 或 `flush=True` 可改善。
  - ★**本机（macOS）无 `setsid` 命令**：RULE 15 的 `setsid nohup …` 配方在此**直接失败**（日志仅 37 字节 `bash: setsid: 未找到命令`，任务根本没起）。**改用** `nohup python3 -u <脚本> > <log> 2>&1 < /dev/null & disown`（2026-09-23 实测：秒级返回、子进程存活并正常跑完 ~110s）。
  - ★**"包装器超时"≠"任务失败"**：用 `subprocess.run(["bash","-lc",cmd], capture_output=True)` 包这条命令时，包装调用本身会挂到超时被强杀（本轮 30s），但 `& disown` 的后台子进程**不受影响、继续跑完**。判结局必须回查 **日志内容 + `pgrep`** 后再下结论。
- 正常日志样例（额度用尽场景）：先列 `新增 N 条` 与每条链接/提取码，再输出 `⚠️ 后续扫描中断：HTTP 403: 今日额度已用完` + `已搜到的新增已照常发送；未扫描部分将在下次继续。`——这是**设计内的优雅中断**，不是故障，此时脚本已自行完成飞书私信+钉钉群推送，外部任务**不得再补推**。

## 全能IT同步机制
- **目标站点**：https://quangneng.com/
- **抓取策略**：直接抓取首页（首页按时间倒序，包含所有分类的最新课程），处理前10个article
- **为什么不判断时间**：首页倒序排列，前10个肯定是最新课程，不需要访问详情页判断时间（速度快60倍）
- **标题提取**：使用 `header h2 a, .entry-header h2 a` 选择器（避免误匹配其他链接）
- **增量同步**：
  - 新课程：加入动态关键词队列
  - 已找到：保留记录但标记 `found=true`
  - 超期未找：搜索次数>30次自动清理
- **避免重复**：同一课程标题只保留一条记录


## 已知缺陷与实测判读（2026-09-22 实测）
- **额度几乎每轮即耗尽（长期常态，非偶发）**：历史报告检索显示 09-09 起 `09-12/13/14/15/16/17/18/20/21/22` 的 haisou 报告**均含"额度耗尽/中断"**；11:15 那轮基本每天都会把当日额度打到 `HTTP 403 今日额度已用完`。
  - 后果：21 个关键词**永远扫不完**（每天只覆盖前缀一部分），同日重复触发（如 11:16 + 11:26）的第二轮必然 0 新增空跑。
  - **可观测性缺口**：脚本无逐关键词进度日志（stdout 两步之间除 numpy 兼容告警外无内容），"扫到第几个词才耗尽"无法从日志得知 → 建议加"每关键词一行"轻量进度日志，或按轮转游标保证每词都能轮到。
- **`is_relevant` 对 "AI+两字中文" 关键词失效**（`haisou_daily.py:131-149`）——**2026-09-27 已修复（R441）**，以下为修复前症状记录：

  - 实测后果（09-22 11:16 轮）：推送的 2 条**全部**来自 `AI测试` 且全为假阳性（一条 AI 短视频课、一条国产 BL 剧集垃圾）。

### 2026-09-30 实测（新增「0 命中即 403」形态 + 零变更机械判据 + 时长基线）

- 步骤1 恢复常态：`抓取到 10 个课程` / 新增 0 / 清理 0 / 待搜 25（09-25 的 `SSLEOFError` 抓取失败**未延续**；池 21→25 的扩张发生在 09-29，今日为稳态）。
- ★**额度 403 有两种形态，判读前先分**：
  - `已命中 N 条后 403`（历史常态，N≥1）⇒ 额度够撑首轮；
  - `0 命中即 403`（**本次首见**，09-29/09-30 连续两日）⇒ 额度在**本轮开始前**已被更早的调用消耗掉（或额度窗口非自然日重置）。
  - 铁律：脚本**无逐关键词/逐请求进度日志** ⇒ 只能报「本轮 0 命中后即中断」，**不可**断言「首个请求即 403」。要定位需先补进度日志（未做）。
- ★**零变更机械判据（比条数强）**：跑前后对 `birdie_monitor/quangneng_keywords.json` 与 `birdie_monitor/haisou_seen_items.json` 取 **sha256 + 条数**；本次 6391B/25 条与 448296B/1426 条**前后逐字相同**（`15b4a19c39d4` / `4f56f30196a9`）⇒ 可机械断言「本轮零写入」，不必依赖 stdout 措辞（脚本会以「去重库已更新」口吻结尾，即便零变化）。
- 时长基线：整轮 **≈63s**（step1 ≈6s / step2 ≈55s；11:15:35 起 → 11:16:38 日志落定）⇒ 后续轮询预算按 ≤2min 给，超时即查日志。

## 2026-10-01 实测补充（请求规模量化 + 403 形态）
