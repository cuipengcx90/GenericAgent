19. 部分提交(「只提交本行」)三坑: ①`git diff -U3` 会把相距 ≤2×context 的多处改动并成**一个 hunk**⇒按内容过滤 hunk 会把他人未提交行一起带上; 判 patch 范围一律用 `-U0`(行级)②暂存后必核验 `git diff --cached -U0` 的**新增行数**与内容标记, 别只看 `--stat`③最稳=直接构造期望 index blob(`git show HEAD:file` 改目标行 → `hash-object -w` → `update-index --cacheinfo`)再 `commit --amend`(★构造 blob 必保文件尾换行:text 模式 write 易丢尾 `\n`⇒多出一个整文件尾 "No newline" hunk 污染提交,落盘后用 `git diff --cached -U0` 数 hunk 数自证只剩自己那处);amend 后复核 `git show HEAD` 只含自己的行、`git diff` 仍留他人未暂存改动(实测 2026-09-23 把他人「自主报告归档」行误带进提交, 即此法回退)。★④`-U0` 只保证行级不跨段并 hunk，**紧邻**的他会话新增仍与你的改动落进**同一 hunk**⇒数 hunk 数不够(实测 2026-09-25 `197faf4`: 自己 2 行与他会话 6 行同 hunk 一并提交=内容正确未丢数据但提交信息与内容不符)⇒提交后必核 `git show HEAD --stat` 的**新增行数**=自己的预期行数，多出即逐行核归属。★2026-09-25 实测(56c0268 误带 3 行他会话改动→e587cb5 经 amend 修正):即便 -U0 numstat 已显示 4/4(自己只 1 行)仍顺手 commit=照样误带⇒**核出不符必须停下重构,勿抱侥幸继续**;修法=`git show HEAD^:<file>` 作基座 + 仅替换自己那一处(assert count==1)→`hash-object -w`→`update-index --cacheinfo`→`commit --amend`(工作区原样保留⇒他人行不丢)。★共享仓 index.lock 僵锁(锁旧+lsof 无句柄=僵锁,勿见"有 git 进程"就当活跃):不删他人锁,改 `GIT_INDEX_FILE=/tmp/x` 临时索引 add/commit 绕过,★提交后必须把该索引原子替换回 .git/index,否则真实索引缺新条目→其他会话 `commit -a` 会把刚提交的文件从 HEAD 删掉。★⑤以 HEAD 为基座构造 blob 时**只把 blob 写进 index,绝不把基座内容写回工作区**（实测 2026-09-25 把 HEAD 内容回写 worktree＝抹掉他会话未提交的 R392/R393 索引行×3 文件；恢复=编号权威 `temp/autonomous_reports/history.txt` 逐字取 history 行 + INDEX 行按公式 `| R<n> | ✅正文 | <history第4字段> | <字节>B <文件名> | <history第5字段> |` 重建，公式须先用 HEAD 中已提交的同批行自证逐字一致）
