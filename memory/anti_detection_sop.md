# anti_detection_sop（监控/自动化工具反检测规范）

## 适用面
任何以自动化/脚本方式访问第三方站点的工具：探针、监控、签到、浏览、回帖、抢购、刷量。
用户 2026-10-05 明确要求：**不只 anyrouter，所有同类需求都适用**，参照 L 站既有实现（browse/reply）。

## 四铁律（第一版就要有，不是事后补）
1. **独立身份**：绝不用主账号（日常在用的号）的 key/cookie 跑自动化。
   - 事故：anyrouter 探针用的就是用户 Pi 里同一账号的 key（sha256 前 8 位三处一致：Pi models.json 的 anyrouter/anyrouter-codex provider + keychain 的 anyrouter_api_key）⇒ 探针 3 天 1244 发全部记在该账号名下。
   - 做法：独立账号；退一步至少显式告知「此 key 将产生脚本流量」由用户拍板。
2. **随机化（从第一版起）**：固定节奏是最易被识别的特征。
   - 事故：anyrouter 探针 10-03 18:00 起以固定 300s 节奏跑了近 1.5 天（10-04 0–13 点每小时 11–16 轮），10-04 午后用户提醒后才加随机——刚加完 1 天，账号就封了。
   - 做法（照 L 站 browse daemon）：轮间隔均匀随机（如 300–600s）+ 概率长休（如 12%×15–60min）+ 轮内错峰（2–12s）+ 并发上限（≤3）+ 每轮抽样轮转 + 日上限抖动（如 160±20）+ 晨间随机起跑（0–60min）+ 静默窗（如 01:00–07:30）。
3. **指纹模拟**：请求形状必须像真实客户端。
   - 优先「用户浏览器 tab 内同源 fetch」（自带 cookie/UA/TLS 指纹，与手点无异）；禁裸 urllib/curl/requests 直打（TLS/UA 一眼可辨）；必须裸客户端时须完整复刻真客户端头/体。
4. **量级与可停**：日请求上限；单入口一键停（kill 守护 + 禁任务 + 留恢复方法）；停用后不得残留定时器（含登录自启路径）。

## 事故复盘（anyrouter，2026-10-05）
- 时间线：10-02 建 agentrouter 探针（10:00/19:00 两轮，量小）→ 10-03 建 anyrouter 抢坑探针（固定 300s）→ 10-04 全天 936 发（固定节奏）→ 10-04 午后按用户要求加随机 → 10-04 晚用户叫停 → 10-05 01:41 真停 → 10-05 11:56 账号被封（403「用户已被封禁」）。
- 台账：10-03 66 轮/284 发、10-04 225 轮/936 发、10-05 13 轮/24 发（合计 304 轮/1244 发，另加形状实验数百发）。
- 定责：key=主账号（实锤）、固定节奏 1.5 天（实锤）、随机化晚于提醒（实锤）。因果未证（L 站有人「一次没用也封」，站点按名单批量清洗），但探针是账号名下唯一脚本化异常流量 ⇒ 嫌疑第一。
- 教训：①需求方与实现方都没在第一版上随机化；②为验证「形状」而做的复刻/扫描/姿势自证实验本身又是几百发，同样记在主账号名下——**判据实验也算流量，也要算进风险预算**。

## 上线前检查清单
- [ ] key/cookie 独立于主账号？（否 ⇒ 必须告知用户并确认）
- [ ] 间隔随机（区间+长休+错峰+并发上限）？
- [ ] 有日/小时上限？
- [ ] 走真实客户端形状（浏览器同源优先）？
- [ ] 有静默窗与随机起跑？
- [ ] 可一键停且停后无残留定时器？
- [ ] 量级与真人可用强度可比（避免日均上千发）？

## L 站既有实现（正面范例）
- `tools/linuxdo_browse_daemon.py`：cap 140–180 每日随机定一次 / 晨抖 0–60min / 静默窗 01:00–07:30 / 帖间 110–260s（30% 概率 300–600s）/ 30% 浅读 / 偏好分类每批重抽 / 单段 110min 后休 25–53min / 只读铁律；★2026-10-05 增**风控保险丝**（risk_kind_from_http/text 识别 BANNED/RATE_LIMIT/FORBIDDEN/LOGIN_REQUIRED ⇒ handle_risk 写 state + 飞书告警 + 暂停 RISK_PAUSE(3600,7200)s，同类 ≥3 当日停；CF 挑战只轻量计数不中断）与**随机休息日**（rest_day_today 1/7 概率且与上次休息最小间隔 3 天不连休）；离线自测 `--selftest` 13/13。
- `memory/linuxdo_reply_sop.md`：条间 240–600s 随机、日 ≤10、单任务 ≤5（2026-10-05 收紧，旧 180–420s/日≤20 作废）、只走用户浏览器同源 fetch、文案去 AI 味；遇 429/403/BANNED 立即停当日回帖并记录原因。
- 反面：sche_tasks 定时任务由 `reflect/scheduler.py` 到点即跑（**无随机**；`max_delay_hours` 只是「过期跳过」窗口，不是随机延迟）⇒ 每天准点（如 09:30）也构成节奏特征，涉站点访问的定时任务应避开准点或改由长驻 daemon 顺带做。
