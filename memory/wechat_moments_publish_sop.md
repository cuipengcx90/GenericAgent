# 微信朋友圈发布 SOP（Mac GUI）

适用: 本机 Mac 微信客户端发朋友圈（文案+配图+隐私分组）。  
工具: `import macljqCtrl as ljqCtrl` + `ocr_utils.ocr_image` + `pyperclip`。  
关联: 群聊日报见 `wechat_signals_sop`（**不是**朋友圈发布）。

> **完成口径（铁律）**: 只有 OCR 在朋友圈 feed 看到「文案片段 + N分钟前/刚刚」才算发表成功。  
> 禁止凭「点了发表」「感觉回到了 feed」口头报完成。点赞/评论须各自 OCR 核验后才可报完成。

## 0. 输入（下次可直接复用）

| 字段 | 说明 | 缺省/询问 |
|---|---|---|
| 文案 | ≤80字宣传向短文；不写具体模型名，可用「AI助手」 | 无则先给用户确认 |
| 配图 | 本机绝对路径（jpg/png） | 无则问用户 |
| 隐私 | 默认「不给谁看」+ 标签「尚饮」 | 用户另指定则覆盖 |
| 评论 | 默认「以上内容和本条评论，均来自 AI 人工智能助手。」 | 可选 |
| 点赞 | 发表后给自己点赞 | 已打通，见 §5 |

## 1. 快速流程（已验证可复用）

```
1. ActivateApp('微信') → ListWindows 取 title=='微信' 主窗 bbox
2. 进朋友圈: OCR 点「发现」→「朋友圈」（每次坐标重取，禁死记）
3. 点右上角相机/发布入口（OCR/坐标，点后必须出现编辑页特征再继续）
4. 选图（§2 Finder 绝对路径）
5. 填文案（§3 剪贴板粘贴）
6. 设隐私（§4 不给谁看 + 标签尚饮）
7. 点「发表」
8. 回 feed OCR 核验: 文案关键句 + 「刚刚/N分钟前」→ 才可报发表成功
9. 点赞/评论: 见 §5（已打通，OCR 动态定位）
```

每步后 `GrabScreen(bbox)` + OCR/像素变化确认；`Click` 后 ~0% 像素变化 = 点歪，立刻停，重算坐标。

## 2. 选图（关键坑已踩过）

Mac 微信走系统文件选择器：

1. 点「从手机相册选择/选择文件」类入口，弹出 Finder 面板
2. `ljqCtrl.Press('cmd+shift+g')` 打开「前往」
3. **必须填配图文件的绝对路径**（含文件名），**禁止**只填到 `temp/` 目录  
   - 反例（已踩）: 填了 `.../GenericAgent/temp` → 空目录 →「打开」无效空转
4. 点「前往」→ 选中文件 → 点「打开」
5. 核验: 编辑页出现缩略图/图片预览，再继续填文案

## 3. 填文案

`ljqCtrl` 无 TypeText。Mac 上：

```python
import pyperclip
# 先点击文案输入区（OCR 或已知编辑区）
pyperclip.copy(文案)
ljqCtrl.Press('cmd+v')   # macOS 是 cmd，不是 ctrl
```

核验: OCR 编辑页能读到文案关键句。

## 4. 隐私：不给谁看 + 标签「尚饮」（已验证）

1. 编辑页点隐私/「谁可以看」
2. 选「不给谁看」（不要「谁可以看/部分可见」）
3. 标签列表可能不直接展示目标 → **用搜索框输入「尚饮」**
4. OCR 定位「尚饮」→ 点击勾选（出现「尚饮(N)」已选态）
5. 点「完成」→ 回到隐私弹窗，应显示「不给谁看 -标签：尚饮」
6. 点「确定」回到编辑页
7. 核验编辑页隐私摘要仍是「不给谁看…尚饮」，再点「发表」

## 5. 点赞 / 评论（✅ 2026-09-12 已打通）

目标: 发表后对自己动态点赞，并评论 §0 默认评论文案。

### 正确流程（禁死记 y；禁合成 hover）
1. OCR 找目标动态时间行（「刚刚 / N分钟前」）取 **y**
2. `Click(2270, y)` —— 双点入口是**常驻**的，**不需要 hover**
3. OCR 确认弹出「赞 / 取消」「评论」
4. 点「赞」；验证：重开菜单应变「取消」，或点赞人行出现
5. 再 `Click(2270, 新y)` 开菜单 → 点「评论」（**点赞后 feed 会因点赞人行上移，必须重取 y**）
6. 等输入区出现（占位「评论」+「发送」按钮）；评论过程中**不要反复 ActivateApp**
7. `Click` 输入区 → `ljqCtrl.Paste(评论文案)` → OCR 确认文字进框
8. `Click`「发送」→ OCR 确认 feed 出现「崔朋：<评论>」才报评论成功

### 已验证失败路径（不要再盲试）
1. ❌ 合成 hover / `SetCursorPos` 轨迹触发不了该按钮（旧认知错误：按钮其实常驻）
2. ❌ 死记时间行 y：点赞后点赞人行出现，feed 上移，y 会变（实测 1511→1425）
3. ❌ 评论过程中反复 `ActivateApp` 可能打断输入框焦点
4. ❌ AX / vision 对本场景不可靠（自绘 UI / 本环境 vision 曾解析失败）

### 坐标量级参考（本机微信全屏物理，仅量级，禁死记）
- 双点入口: `(2270, 时间行y)`
- 赞/取消: ≈`(1974~1995, 时间行y)`
- 评论菜单项: ≈`(2155, 时间行y)`
- 评论输入区: ≈`(1650, 时间行y+170)`
- 发送: ≈`(2200, 时间行y+290)`

## 6. 坐标 / 窗口铁律（Mac）

- `import macljqCtrl as ljqCtrl`
- 一律**物理坐标**；区域图内坐标 → 屏幕用 `ljqCtrl.CropToScreen(bbox, px, py)`
- `SetCursorPos((x, y))` 必须传**元组**
- 每次操作前 `ActivateApp('微信')`；主窗用 `title=='微信'` 取 bbox（别拿子窗口）
- 禁死记坐标：窗口/feed 滚动后全变，一律 OCR 重定位
