# GitHub 项目学习方法论 SOP

适用: 快速理解陌生代码库，定位核心逻辑，完成功能扩展或问题修复。

## 核心原则
1. 结构优先: 先目录树+README建立全局认知
2. 入口追踪: 从启动文件/API入口反向追溯核心流程
3. 实测验证: 边读边跑，执行验证理解
4. 增量记忆: 关键发现立即记录，避免重复探索

## 标准流程
1. 快速扫描(5-10min): README -> docs/ -> requirements.txt/pyproject.toml -> main.py/app.py -> tests/ -> 产出项目定位+技术栈+模块清单
2. 入口追踪(15-30min): 启动命令 -> 主函数 -> 路由定义 -> service/core logic -> 产出调用链+关键类函数清单+数据流路径
3. 实测验证(20-40min): 按README跑起来 -> smoke test -> 改参数看行为 -> 加print/logger追踪 -> 产出最小可运行示例+环境配置清单
4. 问题定位(按需): 错误栈定位 -> 向上追调用链 -> 检查测试用例 -> 小改动验证

## 坑点
- 环境问题优先查issue和discussions
- 依赖版本冲突先看requirements.txt固定版本
- 配置文件缺失先看.example或config.template
- 用git blame查代码历史和commit message

## 知识沉淀(任务结束时)
- L2: 项目路径、核心模块、技术栈、关键配置
- L3: 特定任务的避坑指南、扩展方法
- 禁止记录: 通用常识、可快速查到的API文档

## 检查清单
- 能一句话描述项目作用
- 知道如何启动和测试
- 画出核心流程数据流图
- 记录关键配置和避坑点
