# 根因分析 SOP（root_cause_analysis_sop）

## 适用场景
- 发现异常/低效/失效现象
- 成本/性能问题定位
- 重复失败的系统性原因排查

---

## 标准步骤

1. **收集证据**: 日志+数值+代码，禁凭印象；用`file_read`/`code_run`获取原始数据
2. **量化影响**: 给出具体数字（成本$X/节省X%/延迟Xms），禁模糊描述
3. **假设→验证**: 先提假设，再用代码验证，禁直接断言根因
4. **单一根因**: 优先找最小根因，避免多因素混淆
5. **方案产出**: 含预期收益量化 + 实施风险 + 标注"待审批"，不擅自修改核心代码

---

## 坑点

- 修改核心代码前必须用户审批（CONSTITUTION第1条）
- 预期收益必须基于实测数据，禁拍脑袋估算
- 交叉验证：禁信摘要，数值进详情页核实
- 根因结论格式：「现象 → 根因 → 量化影响 → 建议方案」
