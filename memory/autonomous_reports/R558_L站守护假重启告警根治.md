# R558 L站守护「假重启告警」根治：休眠自声明 + 先停后起（2026-10-07）

**一句话**：07:41 那条「重启失败」告警是**假阳性**——daemon 一直活着，只是在静默窗里按设计长睡；看门狗只认文件 mtime，分不清「卡死」与「有意长睡」。已给 daemon 加心跳自声明（下次预计醒来时刻），看门狗据此判「休眠中」不再重启；并修掉重启路径上 bg_task 同名任务占用导致的 rc=4 死锁。

## 1. 现场（全部回源台账/状态，非印象）

- 用户告警原文：`⚠️ L站浏览守护重启失败 1 次（STALLED_26645s）：已尝试拉起但未成功，将退避重试。· 2026-10-07 07:41:01`
- 台账 `temp/linuxdo_watch/watchd.jsonl`（1648 行，含 79 条 RESTART 行）：06:00–06:19 各轮为 OK 或 STALL_IN_QUIET_WINDOW（quiet=true，静默窗免责）；07:30:58 / 07:35:59 / 07:41:01 三轮 RESTART，reason=STALLED_26042s / 26343s / 26645s，err=`[bg_task] 任务 linuxdo_browse 已在运行（pid=80885），拒绝重复启动`（rc=4）；07:42 起 RESTART_RATELIMIT_3/h 刹车
- 同刻 `n_pids=1`：daemon 活着（pid 80885）

## 2. 真因链

1. 静默窗（01:00–07:30）内 daemon 长睡 ⇒ `state.json` / `browse_log.jsonl` 停更 ⇒ 看门狗的 `last_progress_ts` 只由文件 mtime 派生 ⇒ `age=26045s > STALL_S(3h)` ⇒ 判「停滞」⇒ 决策 RESTART
2. 重启调 bg_task `start --name linuxdo_browse`，而该名字任务正在跑 ⇒ bg_task 拒绝重复启动 rc=4（这是**保护**，不是故障）⇒ 看门狗记「拉起失败」
3. 连续 3 次 ⇒ fail_streak 达阈值 ⇒ 07:41 推送「重启失败 1 次」

⇒ 根因不是站点、不是浏览器会话、也不是进程死了，而是 **daemon 缺少「我正在有意休眠、预计 X 点醒」的自声明语义**，看门狗只能靠文件新鲜度猜。

## 3. 修复（三件）

**A. daemon 侧**（`tools/linuxdo_browse_daemon.py`，+47/−13）
- 新增心跳文件 `temp/linuxdo_browse_daemon/heartbeat.json`：`{ts, epoch, pid, phase, next_wake_ts}`
- 主循环顶写 `write_heartbeat("loop")`（相位=活跃）；单次睡眠封装为 `_nap(sec, phase)`，**睡前**写 `next_wake_ts = now + sec`
- `_nap` 内写心跳失败被 try/except 吞掉，不因心跳异常中断浏览

**B. watchd 侧**（`tools/linuxdo_daemon_watchd.py`，+82/−2）
- `heartbeat_info()` 读心跳，读到即入快照 `next_wake_ts / phase`
- `decide()` 新增前置分支（其前是 `not pids ⇒ DAEMON_DEAD`，故只对**活着的** daemon 生效）：`next_wake_ts > now` 且 `<= RESTING_MAX_S(12h)` ⇒ `OK / reason=RESTING_UNTIL_<phase>_<min>m`
- 重启前先 `stop_daemon()`（bg_task stop --name linuxdo_browse）再 spawn，解 rc=4 死锁；stop 失败 rc=3 不阻断 spawn
- `PROGRESS_FILES` 纳入 heartbeat（mtime 兜底）

**C. 自测**：daemon `--selftest` 35/35 PASS；watchd `--selftest` 90 checks / 0 failed（R556 记 86）

## 6. 口径与坑（已同步进 SOP）

- `next_wake_ts=null` = 活跃（loop 相位），**不是**异常；只有 `phase=sleep/quiet` 才有值
- 12h 上限 `RESTING_MAX_S`：任何「自称要睡超 12h」的声明一律当坏值，回落旧停滞判据（防止「自称休眠」掩盖真卡死）
- 心跳分支**只对活着的 daemon 生效**：`decide()` 里 `not pids ⇒ DAEMON_DEAD` 在前，进程真死照样立即重启
- 静默窗内停滞本就属期待态（`STALL_IN_QUIET_WINDOW`）；真正危险的是**窗后仍停更**，此前正是这里被误判
- 看门狗 3/h 重启速率上限是刹车，不是故障信号；重启前必先停同名任务（否则 bg_task rc=4 恒拒）
- 自测入口：daemon 是 `--selftest`（非位置参数）；watchd 是 `--selftest`
