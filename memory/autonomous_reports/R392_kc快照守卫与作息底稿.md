## 3. 数据字典与可复跑 SQL（验收③）

语料：`temp/kc_snapshots/<日期>/knowledgeC.db` —— **只读**副本（`file:<path>?mode=ro`），
**必须连 `-wal` 一起拷**（R357/规则 17：缺 -wal 会"假空"）。

| 用途 | 表/字段 | 口径 |
|---|---|---|
| 前台事件 | `ZOBJECT.ZSTREAMNAME='/app/usage'` | 应用名=`ZVALUESTRING`；**时长=`ZENDDATE-ZSTARTDATE`（秒）** |
| 熄屏状态 | `ZSTREAMNAME='/display/isBacklit'` | 取值=`ZVALUEINTEGER`（1=亮 / 0=熄）；区间=`ZSTARTDATE..ZENDDATE` |
| 通知 | `ZSTREAMNAME='/notification/usage'` | bundle=`ZSTRUCTUREDMETADATA.Z_DKNOTIFICATIONUSAGEMETADATAKEY__BUNDLEID` |
| ⚠ 陷阱 | `ZVALUEDOUBLE` | `/app/usage` 下系**位型垃圾**（1e19 量级），不得当秒用 |
| 时区 | 全部时间列 | Cocoa epoch 偏移 978307200 秒（SQL 或 Python 侧并入） |

```sql
-- ① 前台事件（时长由此算：ZENDDATE-ZSTARTDATE，秒）
select ZSTARTDATE t, ZENDDATE e, ZVALUESTRING app from ZOBJECT
 where ZSTREAMNAME='/app/usage' order by ZSTARTDATE;
-- ② 熄屏/亮屏行（三态判据：区间含 t 取该行 v，否则 = 空隙 gap）
select ZSTARTDATE t, ZENDDATE e, ZVALUEINTEGER v from ZOBJECT
 where ZSTREAMNAME='/display/isBacklit' order by ZSTARTDATE;
-- ③ 本地日：date(ZSTARTDATE+978307200,'unixepoch','localtime')
-- ④ 小时桶：Python 侧 datetime.fromtimestamp 后按 hour 归桶（与 SQLite localtime 同口径）
```

★ 本报告未重造 R371 的字段矩阵，只把"时长到底取哪列""哪列是垃圾"这类**实测结论**钉死。

## 4. 口径声明（写死，防后续误用）

1. **熄屏只认 v=0**（252.78 h / 37.5%）；「无行」是**混合区**，当场亮处理会高估。
2. 因此**不输出**「窗口 − 熄屏 = 亮屏」（该式给 17.5 h/天，与前台证据矛盾）。
3. 「在场/活跃」用 `/app/usage` 前台事件耗时合计（口径 = Σ(ZENDDATE−ZSTARTDATE)）；`ZVALUEDOUBLE` 不可用。
4. 各流窗口不等长（app/usage 25 天、notification 29 天、isBacklit 29 天），跨流比较先裁公共窗。
5. **v=0 只是"熄屏"的下界**：设备睡眠时该流同样不写行 ⇒ 252.78 h 不能读作"全天熄屏总量"。
6. 本文件所有数值来自 `profile.py` 一次运行（2026-09-25 05:03 快照）；知识库滚动删除（≈4 周），跨日比较必须用已落盘快照。
