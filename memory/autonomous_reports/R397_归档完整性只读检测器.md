## 2. 用法与退出码

```bash
python3 tools/archive_integrity.py                      # 默认检测 memory/autonomous_reports
python3 tools/archive_integrity.py --dir <目录>          # 只读检测任意归档目录

python3 tools/archive_integrity.py --selftest            # 夹具负控自测（夹具建在 temp/，不触真实归档）
```

| rc | 含义 |
|---|---|
| 0 | PASS：无硬性 finding（同号组/缺正文属提示，不影响 rc） |
| 1 | 有硬性 finding：真内容冲突 / INDEX 指向不存在的文件 / INDEX 与 history 编号不一致（双向）/ 有正文但 history 无编号行 / 编号空洞 |
| 2 | 输入缺失（目录不存在） |

判定链（同号组，按优先级）：`SAME`（全部 sha1 相同）→ `CONTAINED`（一方行集合被另一方包含）→ `CROSSREF`（一方正文点名另一方文件名，即附件/拆分对）→ `SPLIT`（行集合 Jaccard ≥ 0.5）→ `CONFLICT`（其余 = 真内容冲突）。行集合口径 = 去首尾空白、丢空行。

## 6. R337：「真内容冲突」判据与处置建议

**判据（本工具的判定链）**：同号不同 sha1 时，先看是否一方正文点名另一方文件名（`CROSSREF`），再看行集合是否互相包含（`CONTAINED`），再算行集合 Jaccard（≥0.5 为 `SPLIT`），**其余**才判 `CONFLICT`（真内容冲突）。

**R337 实测**：

```
28c28b67ce22    9265B  169行 R337_patch_roi_monitor_v2.md
f8683ac633e2   16337B  257行 R337_roi_monitor产出量告警修复(口径v2方案).md
差集: only_a=4 only_b=92 common=165
```

- 小文件正文含「# R337 附：roi_monitor.py v2 候选补丁快照（183 行 unified diff，未落地）」与「验收证据见同目录 `R337_roi_monitor产出量告警修复(口径v2方案).md`」⇒ 它**主动点名**了大文件，属附件/附录关系（`CROSSREF`），**非内容冲突**：它的 4 行独有内容全是"附录头 + 指针 + 状态 + 回滚命令"，其余 165 行是两个文件共有的报告骨架。
- 因此本轮结论：**归档目录现存 0 组真内容冲突**；TODO 背景里「R337=真冲突」应订正为「R337=主报告+附件拆分对」。

**处置建议（待批，本轮未执行）**：
1. **INDEX 指向订正**：R337 行当前指向 9265B 的附件，应改指 16337B 的主报告（附件保留在原地，由主报告正文引用）。同类问题共 7 条（R337/341/349/351/355/356/357）——但 R341/349/351/355/356/357 这 6 组是 sha1 完全相同的改名对，"主文件"只是命名风格的取舍，**只需挑一条口径统一**（建议保中文语义名或保英文草稿名之一，二选一后同步 INDEX）。
2. **真冲突若出现该怎么办**（判据的用处）：`CONFLICT` 必须人工裁定保留哪一份，另一份改名（加 `.superseded`）或移出归档；**绝不自动删除**——两个编号相同的不同正文，很可能一份是被改写前的正文，删错即不可逆。工具在此时给 rc=1 并打印两组行数/差集，足以支撑裁定。

## 8. 与既有工具的互补关系

`tools/autonomous_reports_archive.py verify` 是**按编号抽验**（`--ids` 或前 N 个：重解压、重解析、与归档文件逐字比对），回答"某几个编号的归档正文是否与源一致"；本器是**全量对账**（无需指定编号，回答"整个归档的结构是否自洽"）。两者不重叠：前者防正文失配，本器防编号/索引/文件三方漂移与同号事故。
