## 2 小鸟平替：PanSou 聚合 + 本地查询入口

- **为何是它**：小鸟（birdie）站点 08-08 起 IP 层全球不可达（R442 已裁决退役），
  需一个**不依赖单一站点**的替代。PanSou 是开源自建网盘聚合（抓 57 个 TG 资源频道），
  本机以服务方式拉起（容器/进程见 `temp/pan_search/`），查询走本地 HTTP，不消耗第三方额度。
- **新增** `tools/pan_search.py`：
  - 子命令：查询 / 主题打包 / 去重（`seen.json`）/ 原始落盘（`raw_*.json`）；
  - 噪声过滤内置（短剧、影视、擦边、广告词）——实测把 1530 条砍到 14 条有效；
  - selftest **27/27**（含负控：噪声词必被剔、重复链接必去重）。
- **真跑产物**：`temp/pan_search/raw_20261006-122205.json`（5.84 MB 原始）+ `seen.json`（947B）。
- **边界（必须声明）**：PanSou 聚合的是**他人转发的分享链接**，不校验有效性/版权；
  链接失效是常态；仅作「发现线索」，下载前自行判断。

## 3 海搜：额度到底怎么没的

| 事实 | 证据 |
|---|---|
| 日配额 200 点 | 会员端点 `daily_quota=200` |
| 已用满 | `used_today=200 / remaining_today=0`（2026-10-06 实测） |
| 1 次搜索 = 2 点 | 用量历史 `search: 200` = 100 次搜索 |
| 单轮扫描 ≈147 请求 | (静态 24 + 动态 25) × 3 平台 |
| ⇒ 单轮 ≈294 点 | 超过全天额度，故**跑一轮就没了** |

⇒ 09-24 起连续「403 今日额度已用完」= 真实耗尽（供给侧），重试无意义；
用户「监控把额度用完了，很奇怪」的直觉**成立**。

## 4 减灾落地（`birdie_monitor/haisou_daily.py`，selftest 21/21）

1. **配额预检**：跑前调 `fetch_quota()`；余量不足一次搜索即**零请求退出**（fail-closed，不再空烧日志）。
2. **份额限流**：`HAISOU_BUDGET_SHARE`（默认 **0.35**）⇒ 单轮至多吃掉 35% 余量，
   把大头额度**留给用户手动搜**；同时受 `HAISOU_MAX_TASKS` 上限约束。
3. **轮转游标** `birdie_monitor/haisou_cursor.json`：记 (关键词, 平台) 断点，下轮续扫；
   解决「静态词永远先被扫、后排动态/课程词永远扫不到」的结构性偏食。
4. **进度留痕** `temp/haisou_progress.json` + 日志 `[PROGRESS]` 行：403 前扫到哪、
   发出多少请求**首次可观测**（此前完全不可观测，SOP 已标为盲区）。

新增自测：T5（额度耗尽⇒零请求且错误信息可读）、T6（份额封顶=35 请求）、T7（接口失败 fail-closed）；
T4 之后显式装回计数版 search，避免桩泄漏污染后续用例（本次踩坑并修正）。
