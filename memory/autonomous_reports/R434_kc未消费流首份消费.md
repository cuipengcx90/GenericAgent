口径要点（全部进代码与 `--selftest`）：
1. 同一 app 的多行**先并集再切日**（重叠不得重复计时，T11 相邻合并、T5 跨零点切分）；
2. 晚于 cutoff 的区间不计入（T13 截断；负控 NC13 证明「不截断会多算 1 h」）；
3. 某日无行 ⇒ 报 **UNKNOWN**，绝不写成 0（T8）；
4. 两次运行结果逐字相同（T9 确定性）；只读自证（T10 + `--readonly-proof`）。

## 4. 仅熄屏口径得不出、本次新得的结论（逐条附来源）

1. **通知流入面与前台占用面几乎不重叠**（最强一条）。
   投递 Top2 = lark 2932 + Terminal **2560**，合计 5492/5706 = **96.3%**；
   而 `com.apple.Terminal` 在 `/app/usage` 中 **0 行**（库内 44 个 app 名单里不存在）。
   来源：`notif_by_bundle` ＋ `select count(*) ... and ZVALUESTRING='com.apple.Terminal'` = 0。
   ⇒ 通知密度度量的是「后台任务完成推送」，**不是**注意力投入、也不是被打扰频率。
2. **注意力高度集中于单一工具**：ghostty 92.942 h = 前台总量的 **55.81%**，而其通知投递为 **0** 次。
   来源：`fg_hours_by_app_total`。
3. **前台信号本身有 ~0.6% 不可信**：`/app/usage ∩ 熄屏(v=0)` = **0.981 h / 148 段**（0.981/166.521 = 0.59%）。
   熄屏-only 画像看不见这一层（它只看 `isBacklit`，不知道当时有没有 app 声称在前台）。
   来源：`fg_off_overlap_hours` + `anomaly_top`。
4. **整体驻留比与通知密度**：前台合计 166.521 h，覆盖 25 个有数据日（600 h）⇒ **27.8%**；
   若拿 29 天全窗口（696 h）当分母会得到 23.9%（**伪值**，分母含 4 个无数据日）。
   通知密度 = 5706/166.521 = **34.27 次/前台小时**（分母是前台时长的**上界** ⇒ 该值是**下界**密度）。
   来源：`window` + `notif_per_fg_hour`。
