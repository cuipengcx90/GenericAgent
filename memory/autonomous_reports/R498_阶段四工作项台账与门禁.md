## 4. 交付时修掉的两处真缺陷（顺带，非本项范围）

1. **`doc_state_render` 的静默丢弃**：源解析只认「行首带 `✅/🔶/⬜` 字形」的状态行，遇到 `🔶`（本次新增字形）
   或任何未知字形时**直接跳过**而不是报错 ⇒ 生成块少一整行、`--check` 仍判一致。
   修法：解析前先做「疑似状态行但字形未知」探针，命中即 `Blocked`（fail-closed）；`--check` 与 `--selftest` 共用。
2. **`doc_state_check` 同款宽守卫**：首版把真仓 §7.1 里散文 bullet `- **阶段二**：13 条…` 误判为疑似状态行
   （实测真仓 1 例假警报）⇒ 收紧为「冒号后紧跟状态字形」，并补 `NC13` 负控（散文 bullet 不得判疑似）。

两处都在 `--selftest` 里有可证伪的负控（NC6/NC13），不是「跑绿就算」。

## 5. 坑与边界（下次复用的教训）

1. **盖章必须在目标仓做**（R460 铁律）：`native_tree` 期望的 README 内嵌 `repo: <绝对路径>`，是**仓库局部口径**

2. **`derive_guard` 的 STALE 归因要落到文件级**：本次 `l1_index` 报 STALE（输入 203 个），
   逐文件比对后确认**真变即我方 3 个 `.py`**；`lines` 列的 −1 差是 index 与 `wc -l` 的口径差（bytes 全同）⇒ 不是他会话污染。
3. **部分提交**：`ROADMAP_MASTER.md` 里混着他会话的在制改动 ⇒ 用 blob 法只替换我方 2 处
   （`git show HEAD:<f>` 作基座 + 单处替换 + `hash-object -w` + `update-index --cacheinfo`，不带 pathspec 提交），
   提交后核 `--numstat` 与预期逐字相符；他会话 21 项在制改动**未被吞**（前后条数一致）。
4. **门禁只加严**：本次没有修改 §8.1 任何既有条目、没有翻转任何状态；台账 §1 的 6 条里
