## 3. 为什么 RSS 会"骗人"

同一进程 617 在 10:59:33–11:00:34 的密集采样（`temp/mem3caliber/timeseries_617.txt` 原文，左列 `ps -o rss=`，右列 `footprint`）：

```
10:59:33 | ps_rss=67312 KB | Footprint: 4871 MB
10:59:43 | ps_rss=142976 KB | Footprint: 5000 MB
10:59:53 | ps_rss=271968 KB | Footprint: 5100 MB
11:00:04 | ps_rss=64144 KB | Footprint: 5255 MB
11:00:14 | ps_rss=51424 KB | Footprint: 5288 MB
11:00:24 | ps_rss=111456 KB | Footprint: 5399 MB
11:00:34 | ps_rss=71024 KB | Footprint: 5454 MB
```

同一窗口：RSS 在 **50.2–265.6 MB** 之间跳动（加上 11:06:37 实测的 14.9 MB，观测区间为 **14.9–265.6 MB ≈ 17.8×**），而 footprint 现值**单调上升**（4871→5454 MB，无回退）。

⇒ RSS 只是"此刻还驻留在物理内存里的页数"，页面一旦被压缩/换出就立刻从 RSS 消失；因此：

- **判"内存异常/泄漏"必须看 footprint 现值或 `vmmap` 的 written 趋势**，不能用 RSS 单点值；
- R395 记的 `ps -o rss=18,800KB(18.8MB)` 只是当日某一瞬时的 RSS，**不可当稳态基线**（今日同进程实测 14.9–265.6 MB，相差一个数量级）；
- 反过来，peak 也**不能当现值**：617 的 peak=17408 MB，而现值今天只有 4083–7052 MB（§6）。

## 4. 机制与系统面

**4.1 口径自洽性（617，`vmmap -summary`）**：written=**4.1G**、resident=**92.4M**、swapped_out=**4.2G**
⇒ `resident` ≈ `ps` RSS（两个口径对得上）；`written` ≈ `footprint` 现值（含压缩页）⇒ **A 与 B 的全部差距来自"被压缩/换出"的页**，不是统计口径打架。

**4.2 系统级（11:00–11:06 实测）**

| 项 | 11:00:50 | 11:06:37 |
|---|---|---|
| Pages occupied by compressor | 431,411 页（×16,384 B = 7,068,237,824 B ≈ 6.58 GiB） | 409,899 页（≈6.25 GiB） |
| Pages free | 2,771 页（≈43 MB） | 3,208 页（≈50 MB） |
| swap | total 13,312 MB / used 12,503 MB | total 14,336 MB（自动扩容）/ used 12,990 MB |
| 系统报告空闲 | `memory_pressure` = 30% | — |

⇒ 16 GiB 机器的可用物理内存基本被"压缩器 + 常驻进程"吃满，macOS 靠**自动扩大 swap 文件**维持；这类状态下 `ps` 数字会剧烈抖动（页被压走后 RSS 掉到几十 MB），**格外容易被误读成"内存已经很小了"**。

**4.3 工具边界（实测）**

- `footprint -a`（全机扫描，本想做全机 ≥300MiB 基线）**必须 root**：实测输出仅一句 `footprint: Must run as root.`（证据 `temp/mem3caliber/footprint_all.txt`）；因此本报告的"基线"是**按 RSS 取前 N 名**逐进程打的，不是全机普查。
- `footprint -p <pid>` / `heap` / `vmmap` 对**同用户**进程免 root（本轮全部命中）。
- 本机部分 shell 的 PATH 里**没有 `sysctl`**（实测 `sysctl: command not found`）⇒ 用绝对路径 `/usr/sbin/sysctl`。
