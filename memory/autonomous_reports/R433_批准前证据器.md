## 1. 一句话结论

待批台账（`temp/pending_decisions/`，25 个文件 / 142 个可解析行）里，**「机器可判 + 一条命令就能批准」的只有 14 条**；本工具把「批准一条」从"人工读台账猜后果"变成"**先看证据 → 再决定**"的可审计动作：
`--approve` 之前先跑只读证据卡（前提复跑 + 内存 diff 预览 + 旧证据 STALE 检测），无 `--approve` 时**全程零写盘**（真仓实测 `CHANGED=0`）。

## 2. 命令面

| 命令 | 写盘 | 作用 |
|---|---|---|
| `pending_evidence.py` | 否 | 打印全部台账的**证据卡**（前提结论 + 预览 + 不可逆标记 + 陈旧检测） |
| `pending_evidence.py --premise <台账:ID>` | 否 | 单条细节（前提 + diff 预览 + 来源） |
| `pending_evidence.py --cross-check` | 否 | 与 `view_pending.py` 三口径对账（有 ID 行 / 未决 / 无 ID 行） |
| `pending_evidence.py --readonly-proof` | 否 | **只读自证**：对真树算指纹，前后比对，任何写盘都会报 `CHANGED>0` |
| `pending_evidence.py --approve <台账:ID> --ts <时刻>` | **是** | 唯一写盘路径：在决策单元格盖章 + 记录时间戳 |
| `pending_evidence.py --unapprove <台账:ID>` | 是 | 逆向：逐字还原（sha 还原实测 True） |
| `pending_evidence.py --revers-backfill <台账:ID> --to 1 --reply ...` | 默认**否** | 「批」→ revers 回填：dry-run 打印前后行，`--apply` 才落盘 |
| `pending_evidence.py --selftest` | 否 | 18 项自测（含 7 类负控） |

## 4. 复用与边界（不做的事）

- **复用件零重写**：前提复跑内核走 `temp/pending_decisions/premise_recheck.py`（动态 import，本器只加「卡片/预览/写盘」三件事）；对账语料用 `view_pending.py`。
- **不代改判**：不猜「该不该批」，只回答"批下去会发生什么、前提还成不成立、有没有旧证据已过期"。
- **写盘唯一入口**：所有变更走同一 `--approve/--unapprove/--revers-backfill` 闸门，落盘后立即重读自证。
- **无 ID 行不静默丢**：显式列出 7 行（旧结论「3 行不可批准」是**错的**，见坑 2）。
- 未接线 `complete_task` / 定时（提案见第 6 节）；工具本身不住 memory。

## 5. 本轮踩到的四个坑（已固化在 `--selftest` 里）

1. **对账口径用错键**：`view_pending` 把行 ID 存 `_id` 而非 `ID`（表头写「序」的 `DECISIONS_R343/R344` 根本没有 `ID` 键）⇒ 我按 `r["ID"]` 计数得到"多 8 行"的**假差异**（139 vs 131）。对账必须比 `(文件,_id)` **集合**而非计数，改后真仓一致（142/142、137/137）。
2. **ID 提取回退规则外溢**：`view_pending` 在 ID 不匹配 `^[A-Za-z]{1,3}[-_]?[A-Za-z0-9]{0,6}$` 时回退取首 token ⇒ `DECISIONS_R347` 的 `A. launchd 每日 09:30` 会被认成 ID `A`（于是**并非**不可批准）。工具必须与 pv 逐字同源，否则会出现"我丢行/我多行"的双向误判。
3. **写盘前的逐字复现校验用错了基准**：必须用**原始**单元格拼回 `| a | b |` 与原文行比对（去空格）；若用"改后"单元格比对，任何回填都会误报「无法逐字复现」而拒绝（实测 NC11/NC12 双双失败，根因即此）。
4. **自证不能是恒真式**：早先的变更自证写成了 `any(... or True)` 形态＝**假绿**；现改为 `difflib` opcode 级校验，允许的变更**只有**目标行的一处 replace + 审计行/小节标题，其它一律拒绝（`--apply` 失败即零写盘）。

另：revers 判定里 `IRREVERSIBLE`（不可逆/永久/no rollback）**优先于** `REVERSIBLE`（rollback/git checkout/还原）⇒ 回填 `revers=1` 时必须写入含「不可逆」的文本，否则判定不翻转（NC4/NC4b 正是守这条）。
