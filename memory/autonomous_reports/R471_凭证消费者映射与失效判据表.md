## 2. 工具设计

- 子命令（**位置参数**，非 `--flag`）：`plan` / `probe` / `coverage` / `judge` / `proof` / `selftest`。
- 六个存储探针（全部只判存在性，绝不取值）：
  - `ga_keychain_name` —— 走自建钥匙串**在册名列表**比对（`keys.ls()` 语义，不直读 `~/ga_keychain.enc`）；
  - `macos_keychain_item` —— 走系统钥匙串条目名存在性；
  - `config_var` —— 只查 `mykey.py` 里**该变量名是否存在**（不看值）；
  - `env_var` —— 只看进程环境是否**有该键**；
  - `browser_cookie` —— 只查 cookie **名字**是否在列（不读 value/cookie 值）。
- 四类闸门（任一触发即硬问题，`judge` rc≠0）：
  1. `check_consumers` —— 声明的消费者路径必须存在（`STALE_PATH`）；
  2. token 实况 —— 声明涉及的凭证 token 必须在语料里真实出现（`TOKEN_GONE` / `DECLARED_FICTIONAL`）；
  3. 证据行 —— `symptom.evidence[]` 的 `path:line` 必须存在且该行**逐字包含** `must_contain`（`EVIDENCE_GONE` / `EVIDENCE_LINE_DRIFT`）；
  4. `scan_coverage` —— 全仓扫出的凭证 token 事件必须「已声明或已显式排除」（`UNDECLARED`），防「新凭证偷偷进代码」。
- 判定三态：`OK` / `OPTIONAL_MISSING`（可选凭证缺失，提示级）/ `UNVERIFIABLE`（计数进 `unverifiable`，进入硬问题口径）。
- `proof`：对全部输入文件做 sha256 前后比对，自证**只读**（无写路径）。

## 4. 核心结论

1. **凭证面当前连通**：25 条声明里 14 条 `PRESENT/OK`，11 条 `OPTIONAL_MISSING` 且**全部为「未启用的可选通道/未设置的环境变量」**，非断裂。具体：
   - 6 条 IM 通道（`tg_bot_token` / `discord_bot_token` / `qq_app_id` / `qq_app_secret` / `wecom_bot_id` / `wecom_secret`）本机未配置 ⇒ 消费者 `frontends/*.py` 的 `require_runtime` 明确提示为可选，这是**设计态**而非故障；
   - `mk_typesafe_jev_absent` 是**跨存储命名对照项**（该名在自建钥匙串在册、macOS 钥匙串无同名条目），登记目的是防止两套存储被混为一谈；
   - 4 条 `env_var`（`DPDOMAIN_PASSWORD` / `T0_PASSPHRASE` / `GA_E2E_CONTROL_TOKEN` / `GA_HUB_TOKEN`）在「需要时由用户显式注入」，属**临时注入型凭证**，平时不存在是正确的。
2. **覆盖面无空洞**：全仓扫到 35 处凭证 token 事件（唯一 token 27 个），`UNDECLARED = 0` ⇒ 没有「代码里在用、清单里没有」的凭证；12 条显式排除项（如 `GA_KEYSYM_STYLE` 这类**非凭证**开关）也一并留痕，避免下次又被当成漏登记。
3. **症状→判据可回源**：有症状记录的条目，其证据行都绑到记忆里**已存在且逐字命中**的行（例：`memory/haisou_monitor_sop.md:9` 含 `hs_web_session`、`:98` 含 `403`；`memory/linuxdo_deep_read_sop.md:155` 含 `not_logged_in`）。未被硬闸门命中，说明证据链当前无漂移。
4. **登记面缺口（提示级，非硬问题）**：
   - `mk_genericagent`（macOS 钥匙串通用条目）**探针 rc=0 存在，但没有任何消费者映射**，用途未明 ⇒ 属用户私有事实，本次**只登记不代判、不代删**（见台账 §边界）。
   - 若干条目的症状证据为 `—`（`EVIDENCE_NONE` 提示级）：`mk_claude_code` / `mv_fs_app_*` / `mv_dingtalk_*` / `mv_llm_apikey` 等 —— 它们的失效症状**散落在代码里的 `require_runtime`/异常分支**，未成文进记忆，故暂无可回源的证据行。这是**登记面**的缺口，不是凭证面的断裂；补法=后续把这些症状补进对应 SOP 后再回填 `evidence[]`。
   - 仓外消费者（`llmcore`、`~/develop/herdr-agents/.../channel_probe.py`、`~/.claude`、TMWebDriver 同源 fetch、定时任务、浏览器实体标签）一律标 `EXTERNAL_UNCHECKED`：**只登记不判**，因为本器无法在只读前提下验证仓外运行态。

## 5. 边界与坑（实测）

1. 子命令是**位置参数**：`python3 tools/credential_surface.py selftest`；写 `--selftest` / `--proof` 会 argparse 报 `unrecognized arguments` rc=2（踩过一次）。
2. 运行输出走 **stderr**：`cmd | tail` 会看到空输出（假绿），须 `2>&1` 合并捕获 —— 同 RULE 18⑦「先证校验器真读到语料」的同类陷阱。
3. **不直读** `~/ga_keychain.enc`：自建钥匙串用 `keys.ls()` 只取在册名；系统钥匙串只查条目名存在性。
4. `evidence[]` 挂在 `symptom` 之下（`symptom.evidence`），不是顶层键；统计脚本按顶层 `evidence` 取会得 0（本次实测过一次，已纠正）——写消费脚本前先打印单条 schema（RULE 2/21）。
5. `SURFACE.md` 与台账经 `leak_scan` 复检 `hits=0`（`credentials.json` / `SURFACE.md` / 台账三份均 0），确认登记面与文档里**不含任何凭证值**。
