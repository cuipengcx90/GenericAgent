## 四、可固化SOP节点（优先级排序）

### P0：立即可固化（高频+无SOP）

#### 4.1 `scan_and_analyze_sop.md`
```markdown
# 扫描分析SOP

## 适用场景
- 新目录/文件集合首次分析
- 定期盘点（环境/脚本/配置）

## 标准步骤
1. **列目录**: os.listdir() + 统计文件数/类型分布
2. **抽样**: 按类型各取2-3个样本，禁全量读取
3. **统计**: Counter统计分布，识别异常（空文件/过期/重复）
4. **提炼**: ≥3个模式/发现，量化（百分比/数量）
5. **产出**: 写报告到autonomous_reports/，complete_task收尾

## 坑点
- 禁PS递归/dir遍历，用os.listdir+os.walk
- 大文件只读前200行，禁全量加载
- 数值必须进详情页核实，禁信摘要
```

#### 4.2 `test_and_document_sop.md`
```markdown
# 实测记录SOP

## 适用场景
- 新工具/接口首次集成
- 验证已有功能是否正常

## 标准步骤
1. **最小测试**: 写≤20行测试代码，覆盖happy path
2. **失败路径**: 主动测试异常情况（超时/权限/空返回）
3. **记录行为**: 实际输出 vs 预期，差异点重点标注
4. **提炼坑点**: ≥2个，格式：「现象→根因→解法」
5. **写SOP**: 到memory/xxx_sop.md，patch方式，同步L1

## 坑点
- notify_group超时抛异常（需try/except）
- notify_feishu静默失败（需检查返回值）
- MCP需3步握手（initialize→notifications→工具调用）
```

### P1：近期可固化（中频+有价值）

#### 4.3 `root_cause_analysis_sop.md`
```markdown
# 根因分析SOP

## 适用场景
- 发现异常/低效/失效现象
- 成本/性能问题定位

## 标准步骤
1. **收集证据**: 日志+数值+代码，禁凭印象
2. **量化影响**: 给出具体数字（成本$X/节省X%/延迟Xms）
3. **假设→验证**: 先提假设，再用代码验证，禁直接断言
4. **单一根因**: 优先找最小根因，避免多因素混淆
5. **方案产出**: 含预期收益量化 + 实施风险 + 标注"待审批"

## 坑点
- 修改核心代码前必须用户审批（CONSTITUTION第1条）
- 预期收益必须基于实测数据，禁拍脑袋
```
