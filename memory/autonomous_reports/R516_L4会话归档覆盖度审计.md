# R516 L4 会话归档覆盖度审计器与 180 天真跑（第25批 C2 / TODO L216）

## 0. 一句话结论

给「本机 L4 会话原文归档」建立了**机械可复算的覆盖度判据**：覆盖只能由**权威面**（L4 zip 会话成员名、`all_histories.txt` 的 `SESSION:` 结构头）授予，滚动日志/模型响应只作旁证。
180 天窗口（2026-04-03 .. 2026-09-29）真跑：**归档面内真空洞 0 天**，19 个「空洞日」全部早于归档起点（2026-04-22，不构成补归档诉求），另有 **45 天单源薄覆盖**（只有 L4 zip 一面）、今日（09-29）尚属 L4 滚动滞后待归档。

## 2. 判据（口径即产出的全部价值）

1. **权威面**（授予「该日有原文可回源」）：`l4_zip`（成员名 `MMDD_HHMM-MMDD_HHMM.txt`，zip 名给年月）与 `all_histories`（`SESSION: MMDD_HHMM-MMDD_HHMM` 结构头）。
2. **提示面**（只记 hint，**永不授予覆盖**）：`temp/model_responses`、`temp/desktop_sessions`、`logs/*.log`、`logs/archive/*.gz`。理由：它们含跨日回声（命令输出、报告正文、记忆文本被回显），实测能把 2001-01-01 / 2056-10-21 之类日期刷进命中集——本窗口提示面区间就是这么显示的。
3. **zip 成员名不符即非会话原文**：只计数（`non_session_members`）不授予覆盖（本仓 6 个 zip 该数为 0）。
4. **归档起点 / 边界**：起点＝窗口内权威面最小覆盖日（2026-04-22），边界＝最大覆盖日（2026-09-28）。晚于边界＝待归档（L4 滚动滞后，不计空洞）；早于起点＝`before_archive_start`（窗口本就没有归档面，不计补归档诉求）。
5. **空洞 vs 待归档**：空洞＝起点与边界之间无任何权威面覆盖的日；`hole_days_with_reports`＝空洞日里能在 history 行找到报告编号的日（=「可能丢原话」的最强信号）。

## 4. 独立交叉核验（两条通道，均与工具逐字一致）

**4.1 L4 zip 面（独立 `zipfile` 复算，不复用工具内核）**

```
2026-04.zip members 84 session 84 bad 0
2026-05.zip members 115 session 115 bad 0
2026-06.zip members 56 session 56 bad 0
2026-07.zip members 43 session 43 bad 0
2026-08.zip members 20 session 20 bad 0
2026-09.zip members 174 session 174 bad 0
TOTAL session members 492 distinct days 160 bad names 0
min 2026-04-22 max 2026-09-28
```

与工具 `stats.l4_zip` 的逐 zip 成员数、`distinct days 160`、min/max **完全一致**，非会话成员 0、非会话名 0。

**4.2 `all_histories` 面（独立正则复算）**

```
bytes 10636803 SESSION heads 468 distinct days 115 min 2026-04-22 max 2026-09-28
intersect 115  COVERED-ahist n 45  thin==diff True   ahist-COVERED []
```

- 工具 `stats.all_histories` 报 `{files_scanned:1, session_headers:468, days_recorded:936, bytes:10636803}`——**936 是「起止日期 token 计数」（2×468），不是覆盖日数**；真实覆盖日 115 天，口径须按此读。
- 严格集合判据通过：`薄覆盖日 == COVERED − all_histories覆盖日` 为真，且 `all_histories − COVERED` 为空 ⇒ 两面对账无矛盾，45 天薄覆盖是**真事实**而非口径差。

**4.3 逐 zip 会话密度（成员/天，取自工具 stats）**

## 5. 消费决策（每条附「未来决策 ← 指标」映射）

1. **要回源某日原话** ← `l4_zip` 成员名定位 zip 内文件；`all_histories` 的 `SESSION:` 头只证明「该日存在会话」，不证明正文可取。
2. **要判是否该补归档** ← 看「归档面内真空洞」（今 0）与「单源薄覆盖」（今 45）两个数；早于起点的空洞不构成诉求。
3. **要判是否真丢原话** ← 只有「归档面内真空洞 ∧ 该日有报告编号」（今 0）才值得逐日追。
4. **审计窗口起点取归档起点** ← 早于它的日期一律标 `before_archive_start`，避免读成「丢了 19 天会话」。
5. **今日是否可用** ← 09-29 只有滚动面 ⇒ 属 L4 滚动滞后（与 R514 单日时间线「09-29 交集止 00:26:32」同源现象），不是缺陷；判据是「待归档」而非空洞。

## 6. 边界与残余

- `logs/launch_gui.log`（1211565564 B ≈ 1.13 GiB）超体积上限被记为 `SKIPPED(size_over_limit)`，其覆盖贡献未计入——但它在**提示面**，不影响 verdict。
- 提示面被有意排除在覆盖判定外；若未来要让日志升格为权威，需先解决跨日回声（R466 已量化过同类污染）。
- 本批 TODO 条目原收窄为「近 30 天窗口 + 报告编号关联，不做全历史扫描」：实现上**超出**该收窄（180 天全历史窗口），理由=单次扫描秒级、无外部依赖、且只有全历史窗口才能给出「归档起点 04-22」与「起点前 19 天」这两个判定所需基准；报告编号关联已含（`history_lines` 482 / `days_with_reports` 22 / `hole_days_with_reports` 0）。
- 未接定时/未接 `complete_task`；入口面闸门 `tools/usage_census.py --entries` 真跑 rc=0（本工具带 `selftest` 属可复跑入口，无需登记）。
- 全量扫描耗时秒级（30 天窗口 3.4 s），可随用随跑，无需快照。

## 8. 本批过程中的真缺陷修复（自证用例可证伪）

- **会话头月份/日期拼接错**：`SESSION_RX` 分组为 `(月,日,月,日)`，初版误把首组当整日 token ⇒ `int('')` 抛 ValueError 被 `continue` 吞掉，`all_histories` 面**静默零覆盖**（症状：`days_recorded=0` 而 `session_headers=468`）。修复后补 T14：
  `T14 头计数自证 session_headers=1` / `T14 SESSION 头授予权威覆盖 ['all_histories']` / `T14 正文裸时间戳不授予覆盖（该日 sources 不含 all_histories）[]`。
- **`conclusion_lines` 缺 `return L`**：导致 `render_md` 在 T11 处 `TypeError: 'NoneType' object is not iterable`——自测当场拦住（正是「先证校验器真跑到那一步」的价值）。
- 新增 T15 负控 6 项：归档起点=2026-09-20、早于起点 7 天、**归档面内真空洞 1 天（提示面有、原文无）**、`刚before+inside == holes` 自证、无权威面时 `archive_start=None` 且未知全算真空洞（fail-visible）、md 含结论节与内外拆分行。
