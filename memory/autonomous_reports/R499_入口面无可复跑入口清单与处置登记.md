## 1 结论

## 2 判据（v2）

三档入口识别 `detect_entry`（v2 修正了 v1 的两个假阴性）：

1. `SELFTEST` 档 — 源码含 `--selftest`/`selftest(` 等自检入口；
2. `SUBCOMMAND` 档 — 含 argparse 子命令（`add_subparsers`）⇒ 位置子命令可复跑；
3. `FLAGS` 档 — 只暴露 `add_argument` flag（`--xxx`）；
4. `NONE` 档 — 无任何 CLI 参数解析（可能是**库形态**，被 import 使用，属设计而非缺陷）。

「无可复跑入口」= 分档 ∈ {FLAGS, NONE} **且** 无 `--selftest`、无子命令。

三判据闸门 `guard_entry_disposition`（fail-closed）：

- **UNDISPOSED** — 清单内条目未出现在登记表；
- **CLAIM_WITHOUT_EVIDENCE** — 登记了状态但没有 evidence（或 evidence 指的文件/token 回源不上）；
- **DISPOSITION_STALE** — 给**已有可复跑入口**的工具登记（症状=工具已补 selftest，但登记表还留着"无可复跑入口"的旧账）。

`--verify-entries-json <entries.json>` 提供对已落盘 JSON 的复核入口（闸门与清单同源重算）。

## 5 口径与边界

1. **"无可复跑入口"≠"该删"**：分档只描述入口形态；库形态与 launchd 驱动型都是**合法**形态，故判据是"必须登记处置+证据"，不是"必须补 selftest"。
2. **引用判定禁凭字面**：路径限定名/带扩展名裸名/裸模块名 stem/仓外 LaunchAgents 四源合并（R421 内核），单看仓内 grep 会把 launchd 驱动型误判为死件。
3. **证据必须逐字回源**：登记表的 `evidence` 为 `文件路径 | token` 形式，两个字段都要在真树上命中（本批 12 条逐条回源通过）。
4. **计数快照语义**：本报告所有数字绑定 `entries.json` 的 `generated` 时点；tools 目录随会话增长，复跑数值必然漂移。
5. **基线面**：R421 的 40 个 tools 快照用于回答"R421 之后新增了什么"，不是"当前总数"。
