## 经验教训

### 1. 诊断必须基于实际验证

**错误做法**:
- ✗ 基于"前置不足"推测"工具缺失"
- ✗ 未执行验证命令(find/ls)
- ✗ 诊断结论基于推测

**正确做法**:
- ✓ 执行`find`命令验证工具是否存在
- ✓ 读取工具文件验证功能是否完整
- ✓ 诊断结论基于实际验证结果

### 2. TODO任务规划需要验证环节

**当前流程**:
1. 批判性分析历史
2. 盘点报告提炼线索
3. 产出TODO任务
4. subagent评审打分
5. **缺失**: 前置条件验证+外部依赖识别+重复度评估

**优化流程**:
1. 批判性分析历史
2. 盘点报告提炼线索
3. 产出TODO任务
4. **新增**: 前置条件验证(工具/配置文件/环境)
5. **新增**: 外部依赖识别(smyze项目/GUI/API)
6. **新增**: 重复度评估(与现有报告对比)
7. subagent评审打分
8. **新增**: 可执行性评分(0-100%可在cwd执行)

### 3. 任务设计优先可执行性

**优先级排序**:
1. **P0**: 可在cwd内自主执行(无外部依赖)
2. **P1**: 需要读取外部文件(但不修改)
3. **P2**: 需要外部环境(smyze项目/GUI/API)
4. **P3**: 需要用户协助(配置/密钥/权限)

**R181/R183批次任务优先级分布**:
- P0: 1个任务(11.1%) - R181-#5项目健康度仪表盘
- P1: 1个任务(11.1%) - R183-#1依赖图谱(但与R166重复)
- P2: 5个任务(55.6%) - 需外部环境
- P3: 2个任务(22.2%) - 需用户协助

**结论**: P0任务仅占11.1%，任务设计优先级错误

### 4. 价值评估需要惩罚因子

**当前评分公式**:
```
价值 = AI训练数据无法覆盖 × 对未来协作有持久收益
```

**优化评分公式**:
```
价值 = (AI训练数据无法覆盖 × 对未来协作有持久收益) 
     × (1 - 重复度惩罚)
     × (1 - 外部依赖惩罚)
     × 可执行性系数
```

**惩罚因子**:
- 重复度惩罚: 与现有报告重复度 × 0.5
- 外部依赖惩罚: 外部依赖数量 × 0.2
- 可执行性系数: P0=1.0 / P1=0.8 / P2=0.5 / P3=0.3

**R183-#1任务重新评分**:
- 初始评分: 9分
- 重复度惩罚: 70% × 0.5 = -35%
- 外部依赖惩罚: 0(可在cwd执行)
- 可执行性系数: 0.8(P1)
- 最终评分: 9 × (1-0.35) × 1.0 × 0.8 = 4.7分

**结论**: 优化后评分4.7分，接近实际重估的6分
