# R574 段内帖间长睡缺陷:action_gap 加硬上限 900s

日期:2026-10-11
提交:GA `8c944df`(本地 commit,勿 push)

## 1. 缺陷(实锤)

`tools/linuxdo_browse_daemon.py` 的 `browse_batch()` 帖间休眠为:

```
_base_gap = _ad.gap_seconds("browse") if _ad is not None else random.uniform(*GAP_RANGE)
time.sleep(hu.action_gap("browse", base=_base_gap))     # 修复前:无上限
```

而 `tools/linuxdo_humanize.py` 的 `action_gap(kind, base)` 在 6% 概率的「起身/走开」分支返回

```
_lognormal(r, base * 3.5, 0.5, base * 1.5, base * 12.0)
```

即**单次上限 = base × 12**。当内核 `gap_seconds("browse")` 抽到长休档(base 300–600s)时,
一次 sleep 可到 **2 小时**(600×12=7200s)。

后果两条:
1. 与段预算「6–8 段 × 85–160min」直接冲突——段内出现 2h 静默,段级节律被误表达;
2. 段内长静默触发 `linuxdo_daemon_watchd` 的停滞判据(age > STALL_S 3h 的边缘),
   叠加既有「休眠自声明」语义,仍有被判停滞并重启的风险。

## 2. 修复

- `action_gap(kind, rng=None, base=None, cap=None)`:新增 `cap`,超上限即截断为 `float(cap)`。
  默认 `cap=None` = 行为不变(其它调用点零影响)。
- `tools/linuxdo_browse_daemon.py` 新增常量

```
POST_GAP_CAP_S = 900.0   # 段内帖间单次睡眠硬上限(15min);段级长休归 SESSION_REST
```

  帖间调用改传 `cap=POST_GAP_CAP_S`。

口径:**段内帖间**有硬上限,**段级**长休(段间空档 `rests`)不受影响——长休语义归内核
`day_segments`/`SESSION_REST`,不在帖间叠加。随机内核其它参数一律未动(守 R541
「自动化流量禁固定时刻+固定间隔」铁律)。## 3. 证据
