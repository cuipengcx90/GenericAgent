## 2. 口径（为什么这么算）

1. **体积一律 `du -k`（已分配块）**，不用文件逻辑长度——反例实测：OrbStack `data.img.raw` 逻辑 460.43 GiB、实占仅 14.01 GiB（稀疏文件），用长度会假归因。
2. **候选表复用既有 `tools/cache_reclaim.py` 的 `ITEMS`**（importlib 加载，零改写）；本器只补它未覆盖的目录，不重做全盘归因（那是 `tools/disk_attribution.py` 的活）。
3. 「可再生」三档：`safe`（下次自动更新即重下）/ `approval`（需人批、逐项判）/ `never`（不可再生，永不计入）；无再生方式的目录统一 `unknown`，**不计入**总量。
4. **T0 保护面**以 `temp/t0_baseline.sha256`（6299 文件，状态 OK）为准，四条判据：
   - 候选等于/是某 T0 路径的**祖先** ⇒ `PROTECTED_T0` ⇒ 硬拦、不计入；
   - 候选**自身**即 T0 成员 ⇒ `CANDIDATE_IS_T0_ITEM`（违例）；
   - 候选**内含** T0 文件但自身不是 T0 祖先 ⇒ 逐条提示（`holds_t0`），**只有被计入总量时**才算违例；
   - 基线缺失/为空 ⇒ 必须报 `UNVERIFIABLE`（「没测到」≠「没有」），不得报「无交集」。
   - 修正点：初版把「父目录天然含 T0」当违例，误把每个仓库父目录都判违例（假警报）；现口径下本次真违例 0 例、提示 3 条。
5. **已并入父项（subsumed）只提示、不重复计入**：子项被**「最近的已计入祖先」**吞掉才算——初版取「最近祖先」，导致 `temp/`（5.80 GiB）因父 `/Users/cuip/projects` 是 unknown 而整条从报告消失（真缺陷，已修）。
6. **扫描失败 ≠ 0**：每根独立超时，超时/失败记 ERR 或 PARTIAL（本次 4 根有问题，见 §3.5）；绝不把「没测到」当 0。
7. **本器没有任何删除动作**（不存在 `--apply`）；实际回收仍走既有批准语：`python3 tools/cache_reclaim.py --apply --yes`、R393 的 `--apply --approve "批准回收"`。
