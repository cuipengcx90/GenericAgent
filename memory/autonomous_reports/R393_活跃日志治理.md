## 一、结论（TL;DR）

1. **体积**：`logs/` 现占 **1.7 GB**（`du -sh` 原始输出见 §二），其中 **3 个文件占 1.69 GB**；本次 dry-run 判定 **4 项可回收，净释放 1,570,770,290 B ≈ 1.463 GiB**，回收后 `logs/` ≈ 0.24 GB。
2. **安全性**：11 个日志中 **10 个有 plist 写者（持 fd 写入中）** ⇒ 删除/换 inode 会丢数据 ⇒ 一律走 **copytruncate**（归档前缀 gzip + 尾部写回 + ftruncate，即仓内既有 `tools/log_compress.py` 语义）；唯一无写者的 `launch_gui.log`（孤儿，112.5 天无写入）才整档后删。**副本模拟已证：归档解压 + 保留尾部 == 原文件（sha256 逐字节相等，字节数与换行数完全守恒，diff=0）**。
3. **根因（新发现，值得单列）**：日志体积的主体不是业务日志，而是 (a) `TMWebDriver.py` 把**完整 Tab URL 无条件打印**（其中包含 OAuth `code=` 等凭证），(b) 其心跳行高频重复，(c) 死任务的错误刷屏。**这三个根因导致日志既大又含密**：`launch_gui.log` 1.21 GB / 17,186,285 行，其中 `Tab disconnected` 心跳 1,234 行，而 40+ 字符凭证形状命中 5 行；`scheduler_reflect.log` 同类凭证形状 14 行、`feishu_agent.log` 20 行。
4. **破坏性动作 0 执行**：需要你一句批准（台账 L1）。源码补丁（L2/L3）同样待批。

## 四、根因分析（只读）

### R1 · `TMWebDriver.py` 直印完整 URL（**含凭证**）

掩码后的生产日志真实行（`temp/log_reclaim_evidence.txt`，全部已掩码）：

```
logs/scheduler_reflect.log:240896: ...&code=XXXX****MASKED%3A9IHH****%3AoboCb****&state=5cae**** (Session: 2109071967)
logs/launch_gui.log:1978: {"qrcode":"db269a****","qrcode_img_content":"https://liteapp.weixin.qq.com/q/7GiQu1?qrcode=code****MASKED&bot_type=3","ret":0}
logs/feishu_agent.log:37310: [USER]: https://oapi.dingtalk.com/robot/send?access_token=5a2c****MASKED
logs/feishu_agent.log:37334:   "dingtalk_group_webhook_url": "https://oapi.dingtalk.com/robot/send?access_token=5a2c****MASKED",
```
`(Session: N)` 尾巴即仓根 `TMWebDriver.py` 的 Tab 事件打印格式；该打印**无条件**执行（`grep -n 'print(' TMWebDriver.py` 实测共 16 个 `safe_print` 站点），其中直印 URL 的 5 处为：**L36** `Tab disconnected: {self.url} (Session: {self.id})`、**L65** `Browser http connected: {session.url}`、**L175** `New tab connected: {session.url}`、**L179** `Tab reconnected: {session.url}`、**L283** `成功设置默认会话: … {info['url']}` —— 于是浏览器会话 URL 里的 OAuth code / 机器人二维码链接 / webhook 全 URL 被原样写进日志（另有 L157 `safe_print(self.data)` 直印原始 WS 载荷，属同类风险）。`[USER]:` 回显与配置回显则是上游脚本路径。

高置信凭证形状（`[A-Za-z0-9._%:-]{40,}`）逐文件命中：launch_gui **5** / feishu_agent **20** / scheduler_reflect **14**（合计 39 行；宽口径 `code=|access_token=|refresh_token=` 另有大量假阳性，如 `code=func****`、`code=time****`、`code=1234****`，已剔除后才得到上面的数）。其中 40 位 hex 的钉钉 webhook token：`grep -hcE 'access_token=[0-9a-f]{40}'` → `0 / 5 / 0`，掩码前缀分布为 `5a2c7****`（5 次）与 `6b147****`（1 次）。

修法（**待批**）：`TMWebDriver.py` 5 处 URL 直印改为掩码函数（保留 scheme/host，凭证段 `abcd****`），非 URL 输入原样返回。

### R2 · 心跳行高频重复 → 体量主因

| 文件 | 总行数 | `Tab disconnected` 心跳 |
|---|---|---|
| launch_gui.log | 17,186,285 | 1,234 |
| feishu_agent.log | 2,274,708 | 1,789 |

心跳本身不是行数主体（合计 5,526 行），但**行数规模由会话 URL 打印/浏览器侧输出主导**；`launch_gui.log` 的 17.19 M 行 × 112.5 天无写入 = 典型的**一次性调试期日志被永久留存**（这也是它被判孤儿整档的直接依据）。

修法（**待批**）：`TMWebDriver.py:139` 心跳 print 默认静默，`GA_TMWD_VERBOSE=1` 才打印。

## 五、边界与风险

- **本报告未执行任何破坏性动作**，也未改源码/plist；`logs/archive/` 现有 2 个 gz、实测 `du -sh` = **4.2M**，本轮未清理。
- copytruncate 的固有窗口：归档与 `ftruncate` 之间写入的行若超出尾部保留区，理论上可能落在“已归档”与“已保留”的缝隙；本仓既有 `tools/log_compress.py` 用 **1 MiB 尾部回写**覆盖该窗口，本轮模拟证明**字节守恒成立**（diff=0）。若你要更保守，可先 `launchctl stop` 写者 → 归档 → `start`，但那会中断定时任务，**未采用**。
- 判定“孤儿”的口径：在**代码/配置类型文件**中检索引用并排除报告类 `.md` 与 `temp/`（首次用全仓无限制 grep 耗 6m37s 且被报告文本误命中，已修为限类型快搜）。`launch_gui.log` 最终 refs=**NONE**。
- 本报告不宣称“磁盘从 68% 恢复到 X%”——回收量只对 `logs/` 负责；全盘其它大头见 R385/R391 报告与 `~/.cache` 口径。
