## 2 工具一：`tools/dedup_guard.py`（近重复闸门）

### 2.1 判据（证据一律打印，禁黑箱）

- `jaccard = |A∩B| / |A∪B|`（A/B = 词元集合）
- `contain = |A∩B| / min(|A|,|B|)`（一方几乎是另一方子集时高）
- `strong` = 双方命中同一个硬 token（`tools/`、`memory/` 下的文件路径、`R\d{2,3}` 编号、专有工具名）——不看比例直接判 `STRONG_DUP`
- 判 `DUP` 条件：`strong` 或 `jaccard ≥ J` 或 `contain ≥ C`，且两侧词元数都 ≥ MIN_TOKENS；太短条目一律 `SKIPPED_SHORT`（避免"短文本两两相似"刷屏）

语料 `--corpus auto` = `temp/TODO.txt` 行 + 历史报告标题/首 4 行；批内两两比对（`dup_intra`）双向互报。

## 3 工具二：`tools/todo_quality_gate.py`（候选质量闸门）

### 3.1 判据

- A 机械验收信号（`MECH_PATS`，计数需 ≥ `--min-mech`，默认 2）：`rc=数字`、`selftest`、`负控`、`sha1|sha256`、`git clone|log|status|rev-parse|show|grep`、`grep|SQL|sqlite|find`、`file:...?mode=ro`、`数字+单位(行/字节/条/%/天/次/秒/ms/B)`、`--flag`、`可复跑|可复现|可复算|打印自证|自证`
  - `①②③` 编号只作辅助、不计入阈值（旧格式候选常靠它虚增信号，实测会把空话判成合格）
- B 消费者信号：强信号（消费者/消费/被引用/下游/下一次/下一批/未来/不批后果/不做会怎样/复盘/被谁/谁在用/谁在什么）或 弱信号（报告/记忆/SOP/接线/纳入/归档）+ 产物落点路径样式（`tools/`、`memory/`、`sche_tasks/`、`reflect_scripts/`、`LaunchAgents`、`temp/`）
- C 空话判据：全文只有"提升/优化/完善/增强/关注/梳理/加强/改进"类动词而无 A 类信号 ⇒ `REJECT_VAGUE_ONLY`

拒收码：`REJECT_WEAK_ACCEPTANCE` / `REJECT_NO_CONSUMER` / `REJECT_VAGUE_ONLY`；退出码 `0`=无必拒收、`1`=有 REJECT、`2`=用法/输入错。

### 3.3 三批标定（带标签干跑，逐条判定原样摘录）

标签口径：`kept` = 该轮实际被留用的候选，`dropped` = 该轮被评审淘汰的候选。

第13批（`temp/plan13/prompt.txt`；实际留用 = C1,C2,C3,C4,C5，淘汰 = C6）：

| 模式 | 逐条 | 统计 |
|---|---|---|
| `reject` | C1 PASS / C2 PASS / C3 PASS / C4 PASS / C5 PASS / C6 REJECT_NO_CONSUMER | pass 5, reject 1 |
| `warn` | 同上，C6 降为 `WARN_NO_CONSUMER` | pass 6, reject 0 |

第12批（`temp/plan12/prompt.txt`）：C1 PASS / C2 REJECT_WEAK_ACCEPTANCE / C3 REJECT_NO_CONSUMER / C4 PASS / C5 REJECT_WEAK_ACCEPTANCE / C6 REJECT_NO_CONSUMER / C7 REJECT_WEAK_ACCEPTANCE ⇒ reject 模式 pass 2 / reject 5；warn 模式 pass 4 / reject 3

第10批（`temp/plan10/prompt0.txt`，单行候选老格式）：7 条中 6 条 `REJECT_WEAK_ACCEPTANCE`、1 条 `REJECT_NO_CONSUMER` ⇒ reject 模式 pass 0 / reject 7；warn 模式 pass 1 / reject 6

### 3.4 诚实结论：判据只对当前模板标定过

- 对当前候选模板（候选块多行、带 `验收：①…②…③…`）区分度可用：第13批 5/5 留用条全 PASS，淘汰条 C6 被拦下。
- 对旧格式（第10批单行、第12批偏短）会大面积假拒收（第10批 5/5 留用条全被拒）——根因不是工具算错，而是旧文本确实没写"机械验收/消费者"这两样东西。
- 因此内置 `--consumer-mode {reject,warn}`：默认 `reject`（对应本批验收"缺消费者即拒收"），对历史/旧格式文本一律加 `--consumer-mode warn`，否则读数无效。
- 本轮还踩到一处解析坑：输出格式模板行 `C1: <1-10 整数> | …` 会被 `^C\d+\b` 误当候选吞掉，已修为 "`C<n>` 后紧跟 `:`/`：` 即跳过"，并加回归。

## 6 边界与残余风险

1. 语料是标题级：`dedup_guard` 的历史语料只含 TODO 行 + 报告标题/首 4 行（325 条），正文级重复看不见；加语料会放大误报，属调参取舍。
2. 无语义判定：两器都是机械/词元级，不做 LLM 语义判断；"换个说法说同一件事"只有互换措辞级别才抓得住（NC5 已证）。
3. `SKIPPED_SHORT` 是静默盲区：`tokens < MIN_TOKENS` 的候选直接跳过（第10批 C5 = 34 token 即如此），短候选 = 无覆盖，判读时须看统计里的 `skipped_short`。
4. `--consumer-mode reject` 只对当前模板有效（§3.4），跨模板复用前须重标定。
5. 两工具不改任何东西，也不阻断任何流程；本报告不主张"已接线"。
