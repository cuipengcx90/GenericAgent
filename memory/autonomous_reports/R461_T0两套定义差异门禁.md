### 2.3 新发现：备份面自身也有时点漂移

`defs` 子命令展开当天 `t0_snapshot.py` 的声明集合：

```
声明集合（现在盘上）：485 条
  - memory 359 / kc_snapshots 7 / tools 64 / reflect_scripts 17 / sche_tasks_defs 38
```

而最近一份归档（09-24）只有 **348 成员** ⇒ **137 条已声明但未入最近归档**。原因是归档与 `defs` 展开差 4 天（归档是 09-24 快照，`memory/` 等仍在长）。这本身不是缺陷（归档天然有时点性），但说明**「备份面」若只按最新 tar 判，会把 4 天增量全判成「缺保护」**⇒ 本门禁因此把「声明面」与「归档面」分开表述（`defs` = 声明面，`diff` = 归档面），避免把时点差误读成漂移。

## 3. 工具设计

`tools/t0_surface_diff.py`（只读，纯 stdlib，零第三方依赖）

| 子命令 | 行为 |
|---|---|
| `defs` | 打印两套定义声明面（含各自来源、条数、字节、mtime、sha256 前 16），零写入 |
| `diff` | 计算两方向差集 → 分桶 → 判 rc（`--json PATH` 落 JSON、`--limit N` 控样例条数） |
| `--selftest` | 合成夹具自测 17 项（含 6 类负控） |

`diff` 判据（**fail-closed**）：

- 双侧输入任一不可读/坏格式/非 tar ⇒ `InputError`，`rc=2`（宁可报错不报绿）
- 出现**未登记类别**（新路径模式不在注册表）⇒ `rc=1` + 打 `unclassified`
- 差异中只要存在 `REGISTER` 项 ⇒ `rc=1`；全为 `IGNORABLE` ⇒ `rc=0`
- 路径落到 GA_ROOT 之外 ⇒ 打 `outside_root` 并 fail-closed（防绝对路径泄漏/误判）
- `--accept-file`：登记「已人工确认」的条目后该条不再计入需登记（留痕，不删证据）

注册表（桶规则=单一源，指纹 `2c4dd4c0efd912c1`）把路径模式映射到「类别 + IGNORABLE/REGISTER」，因此**分桶规则不能各改各的**——改规则即改指纹，selftest 里 PC5 会看见指纹变化。

**口径要点（实测踩过）**

- 基线是**绝对路径** ⇒ 必须先剥 `GA_ROOT` 前缀再比，否则交集恒 0（假结论）。
- tar 只 `getnames()`，**不解档**（118 MB，解档既慢又写盘）。
- 归档元数据是 **sidecar 文件**（`<arc>.manifest.json` 348 条 + `<arc>.SHA256SUMS`），**不是 tar 成员**——初版夹具把 `SHA256SUMS` 当成员塞进 tar，导致 6 项自测假失败；改为 sidecar 后 17/17 全绿。真实归档的交叉核对因此走 sidecar manifest（清单 348 / 成员 348 / 缺 0 / 未列 0）。
