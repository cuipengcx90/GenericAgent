## 2. 判据（全部可复算，无隐藏人工判断）

输入三件：`temp/pending_decisions/view_pending.py`（解析台账）→ `premise_recheck.py`（前提复测）
→ `actions.py`（机器可判子集声明，18 条）。分类规则：

| 桶 | 条件 | 本树实测 |
|---|---|---|
| A `approve` 可一句批准 | verdict=ACTIVE ∧ 有消费者声明 ∧ actions 给了证据指向 | 14 |
| B `close` 建议关闭 | verdict ∈ {ALREADY_DONE, STALE} | 1 |
| C `needinfo` 需补证/重写 | REWRITE / NO_PREMISE / 缺消费者声明 / 缺证据指向 | 3 |
| D `human` 需人 | 不在 `actions.py` 18 条声明内 ⇒ **本工具不替其编结论** | 105 |

- **消费者硬约束**（吸收 C5）：`CONSUMERS` 表逐 id 声明「谁消费 / 消费动作 / 不批后果」，
  缺声明一律落 C 桶（该门控在自测里有负控，见 §4）。
- 批准语 = `批准 <台账文件>:<ID>`（如 `批准 DECISIONS.md:C1`），运行时断言全局唯一。

## 6. 本轮自曝缺陷与修正（写下来防再犯）

1. **死 flag**：`--human-full` 一度只加进 argparse、**没有传进 `render_md`** ⇒ 两跑输出同形
   （235/237 行），肉眼与「紧凑生效」无法区分。发现方式=用 CLI 两跑对比行数。已修 + 新增自测断言
   「`human_full` 必须真的让行数变多」。教训：*加了参数不等于接上线*，flag 类改动必须有"行为可辨"断言。
2. **自测夹具覆盖缺口**：夹具只有 3 条机器可判项 ⇒ 上面那条断言在夹具里恒不成立（无 D 桶条目）。
   已补 T9（无前提行）⇒ D 桶与 flag 均进自测覆盖。
3. **门控是真门控**：首跑 T1 落 needinfo，一度以为是 bug，实为 selftest 夹具 id 不在 `CONSUMERS`
   ——即「谁消费」门控**真的在拦**。为此给 `build_entries` 加 `consumers` 注入口（自测注入假表），
   生产路径仍用本文件 `CONSUMERS`，绕不过去。
4. **引用「上一次的输出」必失真**：报告初稿把工具早前的调试打印（`counts: {...}` 与 `approve (14): ...`）
   当作当前输出贴入 §3，而那两行在改渲染时已被删掉 ⇒ 回读 stdout/stderr 才发现（stderr 为空、
   stdout 只有 markdown + `[json] <path>` 一行）。已改为当场重跑取值。教训：RULES 21 的第 N 次复现——
   *即使是"刚才还在"的输出，也可能被自己随后的改动吃掉*。
