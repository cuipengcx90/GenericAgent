## 1. 结论

真跑（快照 2026-09-29T15:54:11+0800，`ga.schedule_registry_audit/v1`）：

> 产物面 31 个 done 家族 / 6067 份回执中，**7 个家族（49 份产物）在四源注册面上全部为空**（sche_tasks 声明、sche_tasks/disabled 归档、LaunchAgents 实装、reflect 在册皆无）。rc=1 表示「存在登记面空洞」，**不等于链路故障**。

其中 3 个家族**同时不在 R411 判据表 targets 里**（quangneng_monitor / wechat_cc_daily_18h / wechat_daily_sqlcipher_output）⇒ 任何在册监控（R411 新鲜度、R457/R464 内容级判据）都看不见它们，属真正的「无人认领」空洞。

## 2. 为什么要有这个器（与既有工具的判据边界）

| 工具 | 看得见什么 | 看不见什么 |
|---|---|---|
| R411 task_freshness | 在册目标的产物是否过期 | 目标一旦从判据表消失就再无覆盖 |
| R488 reflect_wiring_check | reflect 脚本是否被接线 | 只覆盖 `reflect_scripts/` 目录里的脚本 |
| R457/R470 content_change_detector | 家族内容是否停滞 | 分母是判据表 targets∩done 族 |
| **本器 R520** | **有产物但四源皆无登记**（④ 象限） | 不判链路健康、不判该不该退役 |

本器**只回答一个问题**：盘上存在的产物家族，注册面是否认得它。回答「① 已声明 ② 已归档声明 ③ 仅实装 ④ 仅 reflect 在册 ⑤ 四源皆空」中的哪一种。

## 3. 判据实现要点

- 四源：`sche_tasks/*.json`（声明）/ `sche_tasks/disabled/*.json`（归档声明）/ `~/Library/LaunchAgents/*.plist` + `~/.local/share` 之外的 plist 目录（实装）/ `reflect_scripts/*.py`（在册）。
- 家族键复用 R470 的 `done_family_key()`（剥日期前缀与扩展名，不按后缀猜族名——R470 的教训）。
- **匹配用 token 序贯命中，不是子串包含**：`com.test.delta2` 归一化后含 `delta2`，直接子串判定会让 `delta` 家族被邻号 plist 冒充。修前 NC5/NC9 实测失败，修后 22/22 通过。
- 近名登记提示（提示级，不参与判决）：剔除在登记面出现 ≥5 次的通用 token（如 `daily`/`monitor`），再按共享 token 数排序取前 3——不控噪音时提示会刷成 8 条无信息量。
- rc 语义：`0` 无空洞 / `1` 存在 ④（**非故障**）/ `2` 语料或登记面为空（fail-closed，不假绿）。

## 7. 过程中修掉的两个真缺陷

1. **邻号家族冒充**：初版对 plist 文本做子串包含判定 ⇒ `com.test.delta2.plist` 让 `delta` 家族被判「已实装」（NC5/NC9 实测失败）。修为 token 序贯命中，并补 NC7b 专门盯这一类。

## 8. 边界（不做的事）

- 本器**不判**链路是否健康、**不判**某家族该不该退役、**不代**改任何调度文件（`smyze_stock_watch` 的调度在仓外 bar-smyze，`wechat_*` 属历史退役面，处置属政策取舍）。
- ④ 清单的「最新产物日期」只作读数，**不作内容塌陷判据**（任务停跑后 mtime 同样陈旧），该维度归 R411/R457。
- 未接定时、未接 complete_task；入口闸门（usage_census --entries）无需登记（有 subcommand）。
