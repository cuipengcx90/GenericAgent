## 1. 结论

TODO L192 的字面验收（≥3 坏窗口 + ground truth 可查 + 逐例延迟 + 只读自证）**上游 R475 已满足**（6 用例 / 覆盖 6 / 问题 0，延迟 0/0/0/−1 天）。本轮不是重复跑一遍，而是把回放器**从「能跑」硬化到「可被质疑后自证」**，共 4 项增量：

1. **证据出处机检**（`provenance_check`）：每个用例必须在 `preflight_cases.json` 里声明出处 `{authority, case_token, onset_token}`，两个 token 须在权威文件里**逐字命中**；命中失败 ⇒ `PROVENANCE_FAIL` 且**短路**计入 problem（声明即承诺，不再去扫语料掩盖）；未声明 ⇒ 只登记 `provenance_undeclared`，不判失败。
2. **代理信号 vs 实测探针一致性**（`live_agrees`）：回放的历史信号（日志族的坏窗口）与当场真跑的探针状态并排给出，**同向记 True、不同向记 False**，不再让"回放通过"被读成"链路健康"。
3. **形状 fail-closed**：`check_cases` 校验 `provenance` 必须是对象，形状错 ⇒ 报错（NC40）。
4. **负控扩面**：`--selftest` 34/34 → **40/40**，新增 NC35–NC40 六条（出处正例 / onset 查无 / 缺字段 / FAIL 短路不扫语料 / 未声明只登记 / 形状报错）。

**最有价值的一条现场发现**：4 个证据案里 **`live_agrees=False` 占 3 条**（x_ai / haisou / linuxdo）——即"当年前置探针 OK、任务照样坏"。这正是 R475 与 R484 各自独立写下的那句「前置可用 ≠ 产出正常」，现在由机器机械判出并打标，不再依赖人读报告。

## 4. 判读口径与边界

- **出处 = 承诺，不是装饰**：`authority` 写的是这份结论的**权威载体**（本次 3 条落 R467 报告、1 条落 SOP），`case_token`/`onset_token` 必须逐字命中——把「我记得 R467 写过」这种口述变成可机检断言。R467 报告被改写或移动 ⇒ 回放立即 red，避免"引用漂移但结论照旧"。
- **`live_agrees` 只在 live 模式有意义**：`--no-live` 时该列缺省（回放是离线事实，不是今天的健康度）。**禁把 `live_agrees=True` 读成任务健康**：birdie 的 True 是"探针坏 + 链路也坏"的同向，不是好消息。
- **`FIRE_EARLY` 不是缺陷**：x_ai 记 −1 天 = 首次命中早于人工标注 onset，说明 R467 的 onset 标注偏保守；本器只报数不改标。
- **只做回放不改写**：判据表本体、探针集合、推送策略均未动；本器零调度条目。
