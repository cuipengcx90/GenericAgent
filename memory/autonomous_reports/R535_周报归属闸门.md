# R535 周报归属闸门：把「只写与本人相关」从措辞变成机械判据

- 日期：2026-10-01
- 触发：09-28 期周报把**群里他人之间**的对接写进本人周报（门店 3 条）
- 产物：`tools/weekly_report_provenance_gate.py`（593 行 / 29259B / sha256 前16 `401e04aa6e121889`）
- 接线：`memory/weekly_report_sop.md`（+15 行）、`sche_tasks/weekly_report_reminder.json`（prompt 1505→2349 字）、`temp/weekly_report_verify.py`（fail-closed 段）
- 提交：GA `2454e29`（4 文件 / 610+ / 2−）

## 1. 事故与根因

同一批群聊语料共 13 条消息，其中「崔朋」出现 **0 次**，但仍有 3 条门店对接进了正文。SOP 里其实早就写了「只保留与崔朋直接相关（@崔朋 / 崔朋发言 / 回复崔朋）」，但那是**给 LLM 看的措辞**；而 `weekly_report_verify.py` 原有 12 项全部只查版式/收件人/日期，**内容归属零检查**。

即：这是「**规定必须 X 却没有机械 check ⇒ 等于没规定**」的又一个实例（同类：07-24 发错人、07-24 引言导语）。

## 2. 闸门契约（单一源）

`tools/weekly_report_provenance_gate.py`，只读，位置子命令 `check` / `attribution` / `selftest`，退出码 0/1/2。

- content.json 每个 bullet 必须带 `provenance` 数组，取值只认四类 token：
  - `git:<sha>`：该 sha 须出现在本周 git dump 内；
  - `git-repo:<repo>`：本周有提交的仓（仅用于「提交概况」类汇总条目）；
  - `chat:<message_id>`：该消息**必须归属本人**（三条件之一：`sender.name` 是本人 / 正文含本人名 / `mentions[]` 含本人）；
  - `external:<理由≥4字>`：外部指派或长期目标，**唯一人工声明通道**，审阅时单列出来人工确认。
- 缺 provenance ⇒ `PROVENANCE_MISSING`（指名到具体条目编号），rc=1；
- 输入不可用（缺 dump / JSON 坏 / 空内容）⇒ rc=2，**空内容不得判 PASS**。

## 3. A/B 实证（判据有效性）

| 输入 | 结果 |
|---|---|
| 旧 `temp/content.json`（09-30 期事实内容，23 条 bullet） | **23 条全部 `PROVENANCE_MISSING`**，rc=1（点名到条目） |
| 修正版 `temp/content_v2.json`（剔除 4 条他人事项，19 条） | **ALL PASS**，rc=0 |

⇒ 闸门确实能把「别人的事」挡在正文外，而不是只报个笼统红灯。

自测：`python3 tools/weekly_report_provenance_gate.py selftest` ⇒ **27/27 PASS**，rc=0（含本次事故语料复现用例，以及 `external:` 空理由/过短理由的负控）。

## 4. 接线面（三处）

1. **SOP 正文规则**：新增 `provenance` 强制段与「群聊消息归属本人的三条件」；
2. **SOP 流程与门槛**：归纳后先过闸门再生成正文（必须末行 `ALL PASS ✅`，未过禁 HTML/禁草稿/禁通知）；完成门槛新增第 5 条（done 报告须附命令输出与 bullets 数）；SOP 末尾新增「2026-10-01 归属事故」整节（P0）；
3. **定时任务 prompt**（`sche_tasks/weekly_report_reminder.json`）：步骤 4 强制 provenance，新增步骤 4.5「归属闸门」——落 `temp/wr_git_raw.json` + `temp/wr_chats_raw.json` 两个原始 dump（保留 message_id/sha，不留给人看的摘要），跑闸门，未 PASS 禁生成 HTML/禁建草稿/禁通知；
4. **verify 工具**（`temp/weekly_report_verify.py`，gitignored）：新增归属闸门段，fail-closed —— 闸门缺失或 rc≠0 即判 FAIL，`--skip-provenance` 亦判 FAIL（防空跑）。

## 5. 边界与残余

- `external:<理由>` 是**人工声明通道**，闸门只能保证「申报了」，不能保证申报为真 ⇒ 每期需人工扫一眼单列出的 external 条目；
- dump 由定时任务在执行期落盘（temp/ 内，非耐久）⇒ 事后复核依赖 done 报告里附的命令输出；
- 是否用 `content_v2.json` 重生成上周草稿：**未决**（回执显示草稿"未发送"），需用户拍板。

## 6. 教训（通用）

- **「相关性」不等于「归属」**：群里看起来与我们业务相关的事，只要证据链上不是本人推动/承接，就不能写成本人的产出；
- 凡 SOP 用文字规定「必须只写与本人相关的」，都要有一条**能指名到具体条目**的机械 check。
