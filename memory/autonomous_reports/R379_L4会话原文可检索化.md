### 2.1 一次口径差异，查清后写进工具（值得记录的过程）

同一查询 `17463 knowledgeC`：本工具报 `hits=74`，而 `grep -c` 报 73。逐层排查（不是改数就完）：

- 差异不是行切分：`splitlines()` 与 `split("\n")` 计数同为 73（2026-09 内），zip 内 `\r` 字节数 = 0。
- 真因是**大小写口径**：本工具默认 `re.I/ lower()`（等价 `grep -i`），那一行命中的是大小写变体；
  `unzip -p 2026-09.zip | grep -n '17463' | grep -ic knowledgeC` = **74**，与工具一致。
- 于是**新增 `--case-sensitive` 开关**，A/B 双跑留证：

```
$ python3 tools/l4_search.py search 17463 knowledgeC --count | tail -1
[scan] … hits=74 elapsed=3.46s
$ python3 tools/l4_search.py search 17463 knowledgeC --case-sensitive --count | tail -1
[scan] … hits=73 elapsed=2.36s
```
差异只有 1 行，但把它讲清楚比「数字看着差不多」重要：否则日后拿工具与 `grep` 对账会反复自我怀疑。

## 3. 产出物（③ 流式、零解压、零写 zip、零新定时）

| 产物 | 位置 | 说明 |
|---|---|---|
| 检索器（耐久，入库） | `tools/l4_search.py` | 213 行，纯 stdlib；`sha256=895953c57e67e4ca9b68c63d7f14271260bf7830b36128c7f2036d7308d4a73f` |
| 成员清单索引 | `temp/l4_members.json` | 49,020 B；`{"members":[415 条], "totals":{zips:6,members:415,bytes:623272835}}`，每条含 zip/成员/字节/成员内时间戳日期 |
| 验收原始输出 | `temp/l4_acceptance_log.txt` | 3,963 B，本轮所有命令与输出（可复核） |

子命令与用法（`--help` 与 docstring 一致）：

```
python3 tools/l4_search.py list   [--json temp/l4_members.json] [--zip 2026-09]
python3 tools/l4_search.py search 词1 [词2 …] [-k 50] [--any] [--regex] [--case-sensitive]
                                  [--zip 2026-09] [--member 0904] [--context 80] [--count]
python3 tools/l4_search.py show   2026-09.zip 0922_1313-0923_0201.txt [--lines 2015:2017]
python3 tools/l4_search.py grep-file memory/L4_raw_sessions/all_histories.txt R352
python3 tools/l4_search.py selftest
```

要点：`search` 默认**全部词须同行**（AND），`--any` 任一命中，`--regex` 把 terms 当正则 OR；
`--member` 按成员名前缀筛（如 `--member 0904`），配合 `--count` 可秒级做「某天/某月有没有提过 X」。
`show` 免解压回看原文；`grep-file` 把蒸馏态 `all_histories.txt`（75,667 行）也纳入同一套匹配口径。

## 7. 残余风险与边界（如实声明）

- **性能**：无索引 ⇒ 每次查询全量扫 623MB（3.5s，SSD）。这对交互/回溯完全够用；若将来要「每天几十次批量扫」再考虑索引（FTS5 体积不可行，需换倒排/分词方案）。
- **只覆盖 `.txt` 成员**：当前 415 个成员全是 `.txt`；若日后 zip 内混入 `.jsonl`/`.md`，工具会照样按文本读（`_decode` 容错），但**行号语义**是「解码后 `\n` 切分」，与原工具的行号口径需以本报告 §2 的复核方式确认。
- **`--max-member` 默认 200MB** 从未触发（最大成员 32.2MB），该分支目前**无真实样本验证**，仅代码层面成立。
- **`--regex` 命中计数**未做独立互校（只对 `--count` 与 grep 做过互校的是字面词）。
- `temp/l4_members.json`、`temp/l4_acceptance_log.txt` 落在 **gitignored 的 `temp/`**：它们是工作副本/物证，
  耐久的是 `tools/l4_search.py`（入库）。若希望索引 JSON 也耐久，需移到 `memory/` 或 `docs/`——列为待批（与既有 C65/C66「资产住 temp」同族）。
