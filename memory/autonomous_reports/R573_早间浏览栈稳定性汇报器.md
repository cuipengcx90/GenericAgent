# R573 早间浏览栈稳定性汇报器(只读本地·零站点零 token)

日期:2026-10-11 | 工具:`tools/linuxdo_nightly_report.py`(19030B)| 定时:`sche_tasks/linuxdo_nightly_report.json`(08:30 daily,GA_ROOT 锚定)

## 1. 为什么做

用户诉求是「L 站浏览栈到底稳不稳,早上给我一句话」。此前判活只能人工看
`browse_log.jsonl`/`heartbeat.json`,散落五六个文件还要懂字段名。本工具把这些本地台账
压成**一段话 + 一个结论行**,且**完全不碰站点**——不访问 linux.do/connect.linux.do、
不改任何状态、不重启任何进程。零站点请求、零 LLM token。

## 2. 用法与判据

```bash
python3 tools/linuxdo_nightly_report.py run --window-hours 16   # 真发(飞书私信,带幂等)
python3 tools/linuxdo_nightly_report.py run --no-notify         # 只看不发(不写台账)
python3 tools/linuxdo_nightly_report.py run --force             # 忽略当日幂等
python3 tools/linuxdo_nightly_report.py --selftest              # 自测(是 flag 不是子命令)
```

数据源(只读):`temp/linuxdo_browse_daemon/` 下的 `browse_log.jsonl`、`watchd.jsonl`、
`risk_log.jsonl`、`level_log.jsonl`、`ensure_tab.jsonl`、`state.json`、`heartbeat.json`。

结论判定(全由脚本确定性推出,不含 LLM 判断):
- 活动窗零产出 ⇒ ALERT
- 静默窗(01:00–07:30)占比 > 0.6 ⇒ WARN(蓝调不误报)
- 重启失败 > 0 或风控 ≥ 3 ⇒ ALERT
- 重启成功 或 风控 1 次 ⇒ WARN
- 守护不在跑 ⇒ ALERT

## 4. 修的真缺陷

1. **`--no-notify` 也写幂等台账(严重)**:dry 跑一次即把当天标为「已汇报」,
   08:30 真推送被永久短路。修法=dry 分支不写台账,幂等判据只认 `sent=True` 的行。
2. **`read_json()` 缺参**:`cmd_diagnose` 调 `read_json()` 未传路径,selftest 首轮即挂。
   修=`read_json(STATE_REL)`。
3. **分块落盘致函数粘连**(ICON 未提模块级 / cmd_run 未顶格):编译报错,逐个修回。
4. 定时 prompt 台账路径写错(`temp/linuxdo_nightly_report` → 真值 `temp/linuxdo_nightly`),
   已订正,否则记账落到 stray 目录。
