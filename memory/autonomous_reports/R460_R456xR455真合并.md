### 坑 A：`runs/` 是 gitignored 却是派生输入面

`control-plane/*/runs/` 被 gitignore，但**属于 `board_html` 的派生输入**。worktree 里只有 3 个 runs 目录且内容更少，直接跑门禁会出 4 例红：

- `acceptance_v1/test_suite_evidence_check.py` 的 n1/n2（FileNotFound）
- `autonomy_v0/test_lanes.py` 的 t_a1_08/t_a1_15（IndexError）

把主仓 6 个 runs 目录（acceptance_v0 15 / acceptance_v1 14 / autonomy_v0 60 / exec_runner_v0 17 / j0_judge 9 / monitor_v0 3）拷进 worktree 后 4 例全部转绿；`runs/` 不进 `git status`。
**拷完必须重新 `derive_guard stamp`**，否则派生闸门报 DRIFT（本次踩到）。

### 坑 B：native 树里的 README 内嵌绝对仓库路径 ⇒ 盖章不可跨仓移植

在 worktree 里盖章的 manifest 搬到主仓后必然报 DRIFT/RESYNC：`tools/native_plugins.py:291` 生成的 README 内容里带 `repo: <绝对路径>`，manifest 自身也带 `repo` 字段 —— 两者都是**仓库局部口径**。

正确姿势：**在目标仓库内**依次 `l1.py build` → `native_plugins.py build` → `derive_guard stamp`，再 `check`；本次在主仓重做后 `check` 全 OK（`OK=4`），差异只剩 3 行 manifest。

> 注意：不要为这个「跨仓盖章失败」去改 E1 规格 —— `docs/product/E1_DERIVE_GUARD_SPEC.md` 是 `authority_boundary` 门禁的 sha256 豁免基线，改了会报 `FAIL_MODIFIED`。
