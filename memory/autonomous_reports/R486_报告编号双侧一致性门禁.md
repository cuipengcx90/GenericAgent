## 4. 工具设计（`tools/report_number_gate.py`，421 行 / 20091B / sha256 前16 `9f13b2caa581b2b8`）

- CLI 形态：**无子命令**，全部走 flag —— 裸跑＝审计；`--selftest` 跑自测；`--json` 落 JSON；`--proof` 只读自证；`--suggest` 只印建议号；`--propose N` 判某号可用性。（写错成子命令会报 `unrecognized arguments` rc=2：本轮实测过头次把 `audit` 当子命令从而踩到。）
- 判据面 = 四源 + 盘面：`temp/history.txt`（temp 侧 history）、`memory/history.txt`、`memory/history.md`、`memory/INDEX.md`、以及 **两侧报告目录的盘面文件名**（`memory/autonomous_reports/*.md`、`temp/autonomous_reports/*.md`）。文件名计入占用的理由：报告正文可能已存在而索引行缺失（R397/archive_integrity 已见的形态）。
- 建议号算法：从 `memory_max + 1` 起，跳过所有已被占用的编号，取第一个空位。
- severity 分档（本轮新增，解决「存量分叉是设计态、不该让门禁恒红」）：

| severity | kind | 含义 |
|---|---|---|
| ALERT（rc=1） | `MISSING_TEMP_HISTORY` / `MISSING_MEMORY_HISTORY` / `TEMP_AHEAD_OF_MEMORY` / `NUMBER_ALREADY_USED` | 真风险：索引缺失、temp 反超、拟用号被占用 |
| INFO（不抬 rc） | `TEMP_MEMORY_DIVERGED` / `INDEX_ONLY_NUMBERS` / `HISTORY_ONLY_NUMBERS` / `MISSING_MEMORY_HISTORY_MD` | 存量形态量化，只报不改判 |

- `--proof`：对 4 个被读文本文件做跑前后 sha256 比对，输出 `files=N changed=[]`。

## 7. 边界与已知局限

1. 本器只回答「这个号能不能用」，不判内容一致性，也不代改索引（`archive_integrity` 仍负责同号组/覆盖对账）。
2. 「temp 分叉」在本机是**常态**（temp 侧被滚动截断），因此该 alert 定 INFO；只有 temp **反超** memory 才升 ALERT（那意味着 temp 侧写入了 memory 侧不知道的新号，风险方向相反）。
3. 占用面含盘面文件名 ⇒ 若某号只有空壳文件也会被判占用（保守方向：宁可让人核对，不放行覆盖）。
4. 语料口径随索引实时变化：本报告所有数值均为 **2026-09-28 现场快照**，复跑请以工具当场输出为准。
5. **自指窗口（本批实测）**：占用面含盘面文件名 ⇒ 「刚用某号落盘、立刻复跑」会把该号判成冲突（`--propose`），`--suggest` 则会顺延到下一个号。这不是缺陷，但意味着两件事：(a) 本器应在**取号时**跑，而不是落盘后当校验器跑；(b) 收尾顺序上，temp 侧写入新号后、memory 侧索引行尚未补的**窗口期内** `temp max > memory max` ⇒ 会命中 `TEMP_AHEAD_OF_MEMORY`(ALERT)。本轮收尾把双侧索引行**同批**写入，使两侧 max 收敛到同一值，避免把窗口态留在树上，避免把窗口态留在树上——收尾后复跑（§2 run C）实测 `diverged=False`、两侧 max 同为 R486、`alerts: (none)` rc=0，即窗口态确已消除。
6. 与 `archive_integrity` 的分工：本器管「取号前」，后者管「落盘后」（同号组、三源覆盖、缺号）。两者都读 `memory/autonomous_reports/history.txt`，口径已对齐（本器另加 temp 侧与盘面文件名两个面）。
