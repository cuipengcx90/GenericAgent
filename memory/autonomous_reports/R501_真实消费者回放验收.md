## 1 · 要回答的问题

阶段四把多支并行成果并进 main 之后，真正没被回答的不是「能力写完了没有」，而是
**「写完之后还有谁在用、怎么证明它还在用」**。两种常见口径都会撒谎：

* 目录进了 CI ≠ 有人在用：`run_tests.sh` 用 `for d in control-plane/*/` glob 自动发现套件，
  字面 grep 目录名恒零命中（历史踩坑，见 `docs/HOW_TO_VERIFY.md`）；
* 反过来，一个目录没被任何生产代码调用、只躺在 README 里，也不会自己报警。

因此本层只做三件事：**实测消费者（不信声明）→ 对账声明（差异即失败）→ 真跑消费链（跨模块联调）**。

## 4 · 现场缺陷：自测暴露的 `_pipe_counts()` 只解析末行（本会话已修）

**发现**：`census` 全绿而 `run` 报 4 条 FAIL（C3/C2 链各格），失败格 `None`。定位到
`control-plane/consumer_replay_v0/replay.py` 的 `_pipe_counts()` 原本写
`json.loads(proc.stdout.strip().splitlines()[-1])`——只解析 stdout **末行**；而
`control-plane/autonomy_v0/alert_pipe.py` 的 `pipe --json` 用 `json.dumps(..., indent=2)`
输出**多行缩进 JSON** ⇒ 末行恒为 `}` ⇒ 解析失败返回 `None`。

**修复**（提交 `8b3eae6`，2 文件 `48+/4−`；`git show 8b3eae6 --numstat` = replay.py `14+/4−`、test_replay.py `34+/0−`）：
改为「先尝试整串 `json.loads`，失败再回退末行」的容错解析，并补 34 行回归用例。
**A/B**：

| 阶段 | 命令 | 结果 |
|---|---|---|
| 修前 | `replay.py run` | `rc=1`，`claims=36 ok=32 fail=4 negctl=9`（`FAIL C3.pipe_new==1 / None`） |
| 修后 | `replay.py run` | `rc=0`，`claims=36 ok=36 fail=0 negctl=9` |

这是一例典型的「**自测暴露的真缺陷**」：只跑 census 会全绿，只有真回放跨模块调用才暴露
——即 F13 立论「真跑消费链」的直接价值。

## 7 · 边界与残余

1. **census 的判定是引用级**：`CONSUMED` 只证「存在生产消费者」=静态引用，不证「链路在跑」；
   后者由 `run` 的四条链承担，两条一起用才完整。
2. **`run` 覆盖 4 条链而非全部 24 目录**：选的是跨模块/跨仓真联调价值最高的四条；
   其余目录只有 census 级证据（已登记类目与证据命令）。
3. **EXPERIMENT / CI_GLOB 类目是「带证据的登记」而非豁免**：`expect` 快照化，一旦实测 verdict
   变化即报 `MISMATCH`，不会静默漂移。
4. **未接线**：本层未接 `run_tests.sh` 之外任何定时/流水线（套件已由 glob 自动纳入）；
   「每日/每提交自动复算」属待批事项。
5. 阶段门 `stage_gate_check.sh` 步骤 7b（漂移闸门真机 check）在 worktree 内属**脚本自带声明的
   「需本地运行态」**假红（native README 内嵌 `repo: <绝对路径>` = 仓库局部口径，同 R460/R485/R496 铁律）；
