## 1. 事故与任务

`temp/` 整体被 `.gitignore` 忽略 ⇒ `temp/autonomous_reports/`（自主行动报告的唯一副本）长期游离于版本控制，随 temp 清理整体灭失，**reports 目录零 git 历史**。本任务：从可得的灾备源中抢救正文、建立永久入库位、并对"下次不再丢"给出可执行方案。

## 2. 做法与实测结论（关键，可复用）

### 2.1 灾备源勘察（实测，非推断）
| 源 | 内容 | 结论 |
|---|---|---|
| `memory/L4_raw_sessions/2026-04..09.zip` | GA 每 12h 的 L4 会话归档（`reflect/scheduler.py`） | **唯一含报告正文的源** |

### 2.2 正文藏在哪（本任务最大坑，两次踩空）
- **era A（2026-04/05，repr 风格日志）**：正文**不在** `tool_use.input` 里（`file_write` 的 input 被剥离，只剩 `path`/`mode`），而是写在 assistant 文本的 `<file_content>…</file_content>` 标签内。必须做"**同段响应内 标签 ↔ 路径 配对**"，否则一份都取不到（首轮只拿到 3 份）。
- **era B（2026-06 起，JSON 风格日志）**：正文回到 `input.content`（546 次 `/月`）。
- 抽取必须**严格只认 `file_write`/`file_patch`**：用 `startswith("file_")` 会把 `file_read` 算进来，导致"有路径无正文"的假缺口（一度误报 74 份缺口，校正后仅 4 份）。
- 正文标题提取优先级：**原始路径 basename > 正文首行标题**（否则出现 `R296_#_结论.md` 这类垃圾名）。

### 2.3 物理上限（诚实口径）
- 会话日志中**出现过写路径**的报告编号 = 78 个；其中正文可从日志恢复 = **76 个**（缺 98/177/237/296 的完整正文，其中 296 仅剩"结论+记忆更新建议"片段）。
- 索引可见编号 = **335** 个 ⇒ 本轮恢复率 **76/335 ≈ 23%**，不是评审预判的 ~97%。其余 259 个编号的正文在会话日志中**从未留下过原文**（当轮写完后正文即被剥离），属**不可恢复**，不是本工具的能力缺口。

## 3. 交付物（已入库，commit `668fdc7`）

1. `tools/autonomous_reports_archive.py`（新，~320 行，纯标准库）4 个子命令：
   - `repair [--apply]`：从 L4 zip 抽取正文 → `memory/autonomous_reports/R###_<原标题>.md`
   - `inventory [--apply]`：生成 `INDEX.md`（335 行：编号/状态/主题/证据/结论摘要）+ 归档 `history.txt`/`history.md`
   - `verify [--n/--ids]`：**独立复抽**（重新解压重解析）与落盘文件**逐字比对**
   - `sync [--apply]`：把 live `temp/autonomous_reports/` 的当前报告镜像进版本控制目录（幂等）
2. `memory/autonomous_reports/`（新，79 个文件入库）：76 份恢复正文 + `R335` + `INDEX.md` + `history.txt`/`history.md`。
3. 验证证据：`verify` 抽样 14 个编号（R2,3,4,5,6,7 + 178,243,261,296,316,326 等）**全部"逐字一致"**；`repair` 幂等可重跑；`git ls-files memory/autonomous_reports | wc -l` = 79。

## 4. 待审：永久防丢钩子（需改核心代码，未实施）

问题根因 = 报告写在 `temp/`（.gitignore）而 `memory/**/*.md` 是放行规则。三选一（按推荐度）：

- **A. 入库位直接改到 memory（最彻底，改动中等）**：`helper.py` 的 `_REPORTS_DIR` 指向…不宜（helper 属 memory 下可改，但 complete_task 的语义是"temp 工作区→归档"）。推荐做法 = `complete_task()` 落盘后**追加一步镜像**：`shutil.copy2(dest_path, memory/autonomous_reports/)`，并把 `history.txt` 同步到 `memory/autonomous_reports/history.md`。改动仅 `helper.py` 一个文件、单点、失败不影响主流程。
- **B. 复用现有 12h 归档（改动最小，延后 ≤12h）**：在 `reflect/scheduler.py` 的 L4 archive cron 里加一句调用 `tools/autonomous_reports_archive.py sync --apply`（该 cron 已在跑，天然幂等）。
- **C. 加 launchd/反射器 watcher**（最实时，成本最高）：15s 轮询 reports 目录 md 变化即 sync。参照官方反射器模式（轮询零成本），但需新增 plist。

建议 **A + B**：A 保证单点即时，B 兜底任何漏网的写入路径。
