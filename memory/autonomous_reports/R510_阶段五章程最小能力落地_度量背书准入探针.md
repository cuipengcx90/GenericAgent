### 1.3 为什么第 4 项是唯一最高分（J2=3 的依据）

`STAGE5_CHARTER.md` §3.4 为自己列了 5 条「问题发现信号」，逐条在仓内检索是否有机器判据：

| 「请求审批」被错误计为「人工干预」 | `kpi_report` 有 `_interrupt_class`（被迫打断账本分类） | **部分覆盖**（口径在 KPI 面，不在背书面） |

即：**「对外背书」这一层的四件事——分母强制、sim/real 混栏拒绝、`(ws_id, run_id, evidence)` 链接完整性、evidence 内容 hash 稳定性——在仓内没有任何机器判据**。这不是重复实现 `kpi_report`（它管仓内运行 KPI：墙钟/重试/返工/到绿时长），而是给它的输出加一道**对外出示前的准入闸门**。

## 3. 契约草案（实现前公示）

### 3.1 背书包结构 `ga.attestation-pack/v1`

```text
pack/
  ledger.jsonl              # 每行一个 run：ga.attestation-run/v1
  evidence-manifest.json    # ga.attestation-manifest/v1：path → sha256
  evidence/<files>          # 证据正文
```

`ledger.jsonl` 每行字段：`workspace_id`、`run_id`、`simulated`(bool)、`outcome`(字符串或 null)、
`evidence`(列表，元素含 `path`/`sha256`)、`human_actions`(列表，元素含 `kind`)、`approvals_requested`(列表)。

### 3.2 判据（fail-closed，逐条可指认）

| 编号 | 判据 | 失败语义 |
|---|---|---|
| A1 | 分母可定义：ledger 非空且每行 `outcome` 字段存在（值可为 null） | 空 ledger ⇒ `UNSUPPORTED`(rc=2) |
| A2 | sim/real 不混栏：headline 分母只含 `simulated != true`；存在 simulated 行时**必须**分栏输出 | 混栏 ⇒ `NOT_READY`(rc=1) |
| A3 | `(workspace_id, run_id)` 链接：两字段均非空且在同一 pack 内唯一 | 缺失/重复 ⇒ `NOT_READY` |
| A4 | 证据链接与 hash 稳定：每行至少 1 条 evidence；`path` 在 pack 内存在；文件实际 sha256 = 行内声明 = manifest 声明 | 篡改/缺文件 ⇒ `NOT_READY` 并指认差异 |
| A5 | 审批 ≠ 人工动作：`approvals_requested` 不计入人工动作数；`human_actions` 中 `kind` 命中审批语义（`approval`/`approve`/`request`）视为误计 | 误计 ⇒ `NOT_READY` |
| A6 | unknown 不许写成 0：`outcome == null` 的行计 `unknown`，且 `unknown > 0` 时 verdict 不得为 `READY` | 违反 ⇒ `NOT_READY` |

退出码：`0` READY / `1` NOT_READY / `2` 输入或契约问题（UNSUPPORTED）。

### 3.3 负控（对应章程 §3.4 负控草案，逐条）

1. 删除一条分母记录 ⇒ 非零 + 指认
2. 把 simulated 标成 real ⇒ 非零 + 指认
3. 篡改一条 evidence hash ⇒ 非零 + 指认
4. 把「请求审批」改写成人工动作 ⇒ 非零 + 指认
