## 6. 耗时统计（验收⑤）
- 模型加载 4.2s；单条耗时见 §3 表（本机同时负载 16~19，进程实际只拿到约 5 核）。
- 典型：电话通话 920.7s→**580s**（1.6×）；颈椎瑜伽 1114.8s→**350s**（3.2×）；八部金刚功 1007.1s→**312s**（3.2×）；前庭操 519.8s→**125s**（4.1×）；八段锦 728.2s→**60s**（12.2×，因人声稀疏）；纯音乐条目 **2~110s/条**（VAD 直接判空即返回）。
- 合计：本批 24 条计算 **1726.5s = 28.8 分钟**，覆盖 7580s 音频 ⇒ **≈4.4× 实时**。
- 全流程约 1 小时（含首轮 beam5 废弃试验与两次标定，均记入过程日志）。
- ★工程结论：**beam=5 极慢**（首轮 1341s 条目 2.5 分钟未完成即放弃）；**关 VAD 会把音乐段拖成不收敛**（标定实测 120s 音乐段 >3 分钟）；生产配方 = `beam=1 + VAD on + threads=8`。

## 7. 局限与残余风险
1. 26 条有音轨里 ASR 落 **25 个 JSON**：`滇橄榄冰茶.MP3` 与 `.mp4` 的 stem 相同（脚本按 stem 命名）互相覆盖；两条经 VAD 均为纯音乐（0.000），**信息无损**，但如需逐条留档应给输出名加扩展名/哈希后缀（已列为改进项）。
2. `八部金刚功九遍版.mp4` 的 JSON 是**首轮（beam5 配置）产物**，mtime 早于本批，故其"耗时"列不可比（内容仍为 0 字纯音乐，结论不变）。
3. 低置信条目（保健操/崔书娅/8月23日/wxid/bf990）**不可当事实引用**；其中"崔书娅/8月23日 同文本"疑似同一素材，需字节级比对确认。
4. 语音识别对**数字、专有名词、口音**不可靠（通话中的案例编号、人名勿直接采信）。
5. 源文件全在 `~/Movies`、`~/Downloads`、微信/飞书缓存等个人目录，**本报告与 JSON 均属私有数据**；未做任何上传或外发。
