## 1 实现面

子命令（位置参数形式，与其他子命令一致）：

```
python3 tools/course_pool.py match [--min-score 0.62] [--max-per-course N]
                                   [--limit N] [--hits 文件] [--no-pan]
                                   [--include-found] [--apply]
```

- 匹配源 A：海搜已见库 `birdie_monitor/haisou_seen_items.json`（**仓根**，448606B/1427 条；常量 `HAISOU_SEEN`，可 `COURSE_HAISOU_SEEN` 覆盖）。
- 匹配源 B：盘搜原始响应 `temp/pan_search/raw_*.json`（**9 份**；`PAN_RAW_GLOB`/`COURSE_PAN_RAW_GLOB` 可覆盖），产出 `src=pan:<platform>`。
- 判据：课程标题 vs 命中标题的 token 近似打分，`--min-score` 可调。
- 输出 JSON：`hits / courses / min_score / candidates / applied / skipped_existing / matches[]`，每条含 `course_id / course_title / score / src / hit_title`。
- `--include-found` 才把已有资源的课程纳入（用于核 `(cid,url)` 去重）；`--apply` 才落盘。

## 3 口径与坑（本批实测）

1. **apply 去重路径易被误判**：首版 T52 断言 `skipped_existing>0`，实测恒 0 —— 因为课程一旦带上 `resources` 会被「只补空缺」前置逻辑整条跳过，根本走不到 `(cid,url)` 去重分支。修法=第二次跑加 `--include-found` 才会走重复资源判定（修正后断言通过）。
2. **海搜库落点不是 temp/**：`HAISOU_SEEN = BASE/"birdie_monitor/haisou_seen_items.json"`，`BASE=仓库根` ⇒ 真实文件 `<repo>/birdie_monitor/haisou_seen_items.json`（448606B/1427 条）。按 `temp/...` 找会得到「文件不存在」的假结论。
3. **盘搜命中来自 raw 响应而非 seen 库**：`PAN_RAW_GLOB=temp/pan_search/raw_*.json`（本次 9 份），`seen.json`（1378B）不参与匹配 ⇒ 「seen 很小」不等于「盘搜没料」。
4. **SOP 命令漂移已修**：SOP §八原写 `--course <id>`（子命令不支持）⇒ 本批同批改为真实 flags。

## 4 边界与风险

- 匹配是**标题 token 近似**（阈值可调），不是人工确认 ⇒ 默认 dry-run，`--apply` 才写盘。
- 全程零站点请求（只读本地命中库）⇒ 不消耗海搜 200 点/日额度。
- 匹配质量依赖命中标题可读性；同一条命中可能同时贴到多门课（如 Hermes-Agent 命中同时进 1026/1012）。
