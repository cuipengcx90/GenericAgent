## 2. 口径铁律（全部沿用既有记忆，本器只执行不发明）

1. **跨源禁互推**：只在三主源覆盖窗口的**交集**内判定；交集外一律 `unknown`，**绝不补零、绝不记为「不可解释」**。
2. **kc 迟写回填**（R462）：kc 的「今天」在快照时点不可用 ⇒ 覆盖上界取该快照 `max(ZCREATIONDATE)`（cutoff），下界取 `min(ZSTARTDATE)`；快照按「对本日覆盖秒数最大」选，平手取较新者。
3. **chrome 累积库**：上界取 `min(日末, History mtime)`，下界取日首。
4. **pmset 按日轮转**：存在 `<YYYY.MM.DD>.asl` 才算覆盖；上界 `min(日末, events.json mtime)`。
5. **wifi 不参与判定**：缺源不影响 verdict（用例 T4a–T4d）。
6. 时区一律本地时间（与 `kc_app_usage` / `sleep_source_crosscheck` 同口径）。
7. 分类计数是**重叠计数器**（`fg` / `fg_browse` / `browse` / `unexplained`），不是严格划分：`fg_and_browse_minutes` 会同时计入 `fg` 与 `browse`。

退出码：`0` 正常；`1` 分析完成但有告警；`2` 输入/口径错误（非法日期、主源缺失、无共同覆盖、`--as-of` 混用快照）。

## 4. 本会话修的两处真缺陷（发现即修，已补回归）

1. **CLI 把「未指定」当「显式禁源」**：`main()` 把 `--kc/--chrome/--pmset` 的 `None` 一并下发给加载层，导致真实端到端**全源判缺失**（首跑 render 直接报主源缺失）。修法＝仅下发非 `None` 项，未指定的源走自动发现。回归用例 `T5c`（CLI 未指定源 ⇒ 自动发现 rc=0）、`T5c2`（输出非空）、`T5d`（显式给正确 `--kc` 亦 rc=0）、`T5e`（三主源都禁 ⇒ `MISSING_SOURCE`）。
2. **缺失提示里的快照名取错**：原用 `os.path.dirname` 取「可用快照列表」的名字，恒显示 `kc_snapshots×N`（同名前缀无语义）。改为取快照目录自身名 ⇒ 提示可定位到具体日目录。回归用例 `T5e2`「提示含真快照目录名 2026-03-10」。

> 教训（再次命中）：改长文件前必须按 `repr` 读原文再定锚点，凭印象写续行会导致锚点误配、白跑一轮。
