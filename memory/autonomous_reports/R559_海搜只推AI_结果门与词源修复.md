# R559 海搜「只推 AI」：结果门 × 词源双闸修复

- 日期：2026-10-07　仓库：~/projects/GenericAgent
- 触发：用户原话「你这个答案搜了怎么一堆烂东西？我说了我只要AI相关的…是根据什么搜索词怎么搜出来 Hadoop？」
- 一句话结论：**海搜链路此前只有「标题是否含本次查询词」这一条自指判据（搜啥推啥），没有任何 AI 领域校验**；本次新增单一源 AI 判据 `tools/ai_topic.py`，在**查询侧（不发请求）+ 结果侧（不发推送）**双闸拦截，并清理已被污染的词表数据。

## 1 根因（两层，均可回源）

1. **判据自指**：`birdie_monitor/haisou_relevance.py` 只校验「标题是否命中 query token」，命中即推送 ⇒ 搜 `Hadoop 系统入门` 必然推 Hadoop 课程，无 AI 领域约束。
2. **词源污染**：课程词并表把 imooc 的**云计算&大数据/运维方向**课程词并入搜索词表 —— `birdie_monitor/pool_keywords.json` 里 12 条中有 8 条非 AI（Docker×2 / Hadoop / Spring Cloud / K8s / Spark / Flink+ClickHouse / Go 微服务）。

## 2 修复（单一源 + 三处接线 + 数据面清理）

1. **新增单一源判据** `tools/ai_topic.py`（严格档）：ASCII 关键词走**整词**匹配（避免 `ai` 命中 `fair` 之类），中文短语档 `POSITIVE_PHRASES`，`NEGATIVE_*` 仅用于解释不被采纳为正向；`is_ai_topic(title)` 是唯一出口。selftest 42/42（含负控：Hadoop/Docker/K8s/软件测试标题必拒，AI agent/Claude Code 必放行）。
2. **查询侧门**（`birdie_monitor/haisou_daily.py`）：动态词与静态词在**发请求前**过滤，非 AI 词一个请求都不发（含 `[AI查询门] 静态词过滤: 24 -> 10（14 个非 AI 词跳过）` 留痕）。
3. **结果侧门**：命中标题再过 `is_ai_topic`，被拒者计入 `AI_SKIPPED`、不进推送；开关 `AI_GATE_ENABLED`（默认开）。
4. **词表写入侧**：`tools/course_pool.py` 的 `pick_for_words` 加门 ⇒ 未来并表**不会再写进非 AI 词**。
5. **同步侧**：`birdie_monitor/sync_quangneng.py` 同门。
6. **数据面清理**（可逆，备份 `temp/r559_backup/<ts>/`）：`pool_keywords.json` 12 → 4（移除 8 条非 AI）；`quangneng_keywords.json` 26 → 20（移除 6 条非 AI：Vibe Gaming / 系统规划与管理师 / AE 影视后期 / FDE 企业项目 / WorkBuddy / Go 堡垒机）。清理后两份文件的非 AI 残留均为 **0 条**。

## 5 坑与边界（本次实测）

1. **脚本无 CLI 解析时，`--selftest` 会被静默忽略并真跑**：`birdie_monitor/sync_quangneng.py`（144 行）没有 argparse，`__main__` 直接执行同步（L142）。我照例用 `--selftest` 探测时它真去打了 quangneng.com 首页并写了词表（`quangneng_keywords.json` mtime 14:07 即那次写入）。教训：对没见过的脚本先用 `grep -n "argparse\|sys.argv\|__main__"` 判断它到底认不认参数。
2. **A/B 取数只有日志可用**：`birdie_monitor/haisou_seen_items.json` 里按 `last_search_at` 筛 10-07 得 **0 条**（seen 只记已推送标题及最近搜索时间），所以今日 37 条的权威副本是运行日志 `temp/bg_task/logs/haisou_run.log`（26331 字符 / 467 行）。凡要复算「今天推了什么」，一律以日志/回执为准，别用 seen 反推。
3. **污染词是从池子里倒灌进搜索词表的**：`pool_keywords.json` 12 条里 8 条属大数据/云计算/Java 方向（Hadoop、Spark、K8s、Docker…），这些原本是 imooc 课程词，被「课程词并表」直接写进搜索词表，于是每天搜什么就推什么。修法=查询侧一律过 `ai_topic`（已接线三处：海搜查询词、结果门、课程池取词）。
4. **残留（本次不处理）**：留存的 8 条里，同一门课有多个来源变体（`Python3 入门人工智能` 系列 3 条不同来源标题）⇒ 结果侧仍有「同课多名」重复，属去重问题而非主题问题，另立。

## 6 开关、观察点与复跑命令

**开关**（`birdie_monitor/haisou_daily.py`）：`AI_GATE_ENABLED = True`（L36，默认开）。三处接线=查询词过滤（L363–369）、结果门（L446–447，命中即 `AI_SKIPPED[0] += 1`）、运行摘要（L513/L517–518，会打印「丢弃非 AI 命中 N 条」）。要临时放开可把该常量置 False（自测亦用它做开关态覆盖：L568/L797）。

**下一个观察点**：10-08 11:15 那轮 daily 的 done 回执里，第⑤步应出现 `[AI结果门] 丢弃非 AI 命中 N 条`，且推送项里不再有 Hadoop / Docker / K8s 一类词；若 N=0 且仍见非 AI 标题，说明有别的入口绕过了门（下一处该查的就是新增的数据源脚本有没有引 `ai_topic`）。
