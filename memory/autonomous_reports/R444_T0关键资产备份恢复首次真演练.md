## 4. 「可恢复」的判据定义

判 `RESTORED_OK` 需同时满足：成员在归档中存在 → 抽取成功 → 恢复副本 sha256 与归档自带清单一致 → 非空文件。三种失败态显式区分：`MISSING_IN_ARCHIVE`（归档里根本没有）/ `RESTORED_MISMATCH`（内容损坏）/ `EMPTY`（0 字节）；若归档缺少 manifest 与 SHA256SUMS 则标 `no_archive_record`（本次 0 条），此时按「存在且非空」判 OK，不冒充校验通过。
另有两条旁证轴列在表内：**归档 vs 基线**（`vs_baseline_mismatch`，说明备份比基线更新）与**归档 vs 活文件**（`live_axis`）。

## 5. 耐久性发现（本轮新增，属"下一步决策输入"，非本批动作）

**D1 归档只覆盖 T0 保护面的 4.68%。** 归档 348 成员 vs `temp/t0_baseline.sha256`（942309 B，6299 条）：归一化后 **交 295 / 仅归档 53 / 仅基线 6004 ⇒ 295/6299 = 4.68%**。归档自身分层为 `L1:1 / L2:1 / L3:87 / OTHER:259`，sets=`{'memory': 269, 'kc_snapshots': 5, 'tools': 21, 'reflect_scripts': 16, 'sche_tasks_defs': 37}`。
★**口径坑（本轮踩到）**：`t0_baseline.sha256` 存的是**绝对路径**，归档成员存的是**仓内相对路径**；不归一化直接取交集会得到 `0`（并伴随"archive_only 348 / baseline_only 6299"），是**假结论**。本报告的数据已归一化（剥掉 `/Users/cuip/projects/GenericAgent/` 前缀）。

**D2 备份有时效性。** 12 条里 **6 条 `LIVE_DRIFT`**（L1、L2、haisou/scheduled_task/linuxdo 三条 SOP、`sche_tasks/navicat_trial_reset.json`）：归档记录的是 **2026-09-24 09:32** 的时点，现场此后已改。⇒ 恢复演练只能回答「能否回到 09-24 那个时点」，不能回答「能否找回今天的状态」；生产恢复须先明确 RPO。

**D3 两套「T0 定义」不同源。** `reflect_scripts/03_daily_report.py` 在归档内但**不在** `t0_baseline.sha256`（`NO_BASELINE`）⇒「保护面（基线 6299）」与「备份面（归档 348）」并不是同一集合，二者必须显式对齐，否则会出现「以为保住了、其实没进备份」。

**D4 基线里 2 条引用盘上不存在且不在归档内**：`memory/autonomous_reports/R002_reflect脚本审计报告.md`、`R003_SOP覆盖盲区审计.md`（全仓 grep 0 命中；归档亦无）。与 R418 观察到的「同号组/编号复用改名」现象一致（现盘 R002/R003 已是 `_multica_runtime` / `_loopx_recheck`）。正文是否仍可从 L4 月度归档恢复属既有工具 `tools/report_body_recover.py` 议题，本批**不判为数据丢失**，仅登记。

**D5 本轮修掉的工具缺陷（已在同一批修好并加负控）**：抽样预读「内容首 200 字节」时，若 200 字节边界正好落在**多字节字符中间**（中文文件几乎必然触发），`decode('utf-8')` 抛错 → 被当成「二进制」而回落成 **hex**，读起来完全不可用。修法：先裁掉 ≤3 个尾部字节再解码 + 用 NUL 判二进制；并新增自测负控两条（H 多字节边界仍判文本、I 含 NUL 判二进制），`--selftest` 由 16 项升到 **18/18**。旧版 `details.json` 里 L1/L2 的 preview 是 hex 即此因（现已是可读文本）。
