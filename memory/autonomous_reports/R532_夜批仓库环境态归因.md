- 时间：2026-09-29 22:1x（快照口径：herdr-agents HEAD=1cfeab1）
- 触发：用户问「7 天不能烧 token 那怎么测无人值守质量与稳定性」→ R530 搭了零额度夜批；首次真跑（21:27 挂载版）**rc=1**，
  而我按同 rev 在干净树复跑 **42 套件全绿** ⇒ 该 rc=1 是**环境事实**（主仓 41 项未提交改动）而非能力退化。
- 本件：把「仓库环境态」做进夜回执，并让 streak/watchdog **只加标注、不改判据**，防止未来 7 夜把脏树假红读成能力崩。

## 二、实现

1. `record-night` 新增 `--repo-rev` / `--repo-dirty`（未提交条数）；**负数 ⇒ rc=2 且零写盘**（fail-loud，不许静默当 0）。
2. `receipts_per_night()` 逐夜聚合 `repo_dirty`（同日多回执取 max）与 `repo_rev`。
3. `compute_streak()` 每夜给 `env_dirty` / `receipt_repo_dirty` / `repo_rev`，顶层给 `env_attribution` 列表。
4. `print_streak` 该夜行尾打 `+ENV_DIRTY(38项未提交)`，汇总处再给一行「失败不可单独归因于能力，先排环境（判据=同 rev 干净树复跑）」。
5. `watchdog` 的 `failed_nights` / `last_receipt` 同样带 rev/dirty 并打归因提示。
6. `nightly_batch.sh` 落回执时采集 `git rev-parse --short HEAD` 与 `git status --porcelain | wc -l`，计划里打印「仓库态」行。

**口径铁律**：归因**只加标注、不改判据** —— `env_dirty=True` 的夜照样按原判据算（仍 NO_RECEIPT、仍不达标），
避免「一切失败都推给环境」。负控锁死两个方向：同 rc=1 但仓库干净 ⇒ `env_dirty=False` 且 `env_attribution=[]`。
