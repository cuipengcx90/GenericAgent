## 1. 缺陷①：重启丢数据（段级节律）

**症状（R545 实测）**：daemon 把「今天第几段、段何时结束」记在**进程内变量**里 ⇒ 守护一被杀重启，段位从头算，`SESSION_REST`（110min 段满才休）几乎**永不可能达成**。证据=10-05 全天 102 帖 / 21.05h，帖间间隔中位 404s、≥25min 的仅 2 处（恰为静默窗与风控暂停），长休从未发生。

**修法**：当日活动段改为由内核**按日期种子确定性派生**（`linuxdo_antidetect.day_segments(day,'browse')`），段间空档用 `wait_hint()` 等待 ⇒ 重启不重置段位（`_day_segments_cached()` 带当日缓存，`_SEG_CACHE`）。

**验证**：daemon 自测新增 T15（同日段表两次取值逐字相同）、T15b（段表无乱序/重叠/零长）、T15c（段内 `in_segment=True`、段外 `wait_hint>0`）；自测 `32/32 PASS`。

## 2. 缺陷②③：看门狗重启风暴 + 停滞判据单源（同根）

**症状（R545 + 本次现场）**：10-05 9h20m 内重启 35 次；本次现场统计 `temp/linuxdo_watch/watchd.jsonl` 今日 429 行：`OK 227 / RESTART_SKIP 76 / RESTART 41`，即**今日已尝试重启 41 次、另 76 次被冷却挡下**；判据恒为 `STALLED_38xxx s`，而它的「停滞」只读 `browse_log.jsonl` 末条时间 ⇒ 一旦长休/静默窗/环境不可用，末条自然变旧，看门狗就把「正常的长休」判成「死了」。

**看点**：11:14:01 一轮 `ROUND RESTART reason=STALLED_39527s`，而 daemon 是 11:13:57 刚起的（4 秒前）——**新起的守护立刻把刚接管的 daemon 判死并尝试重启**（该轮还伴随 `NOTIFY_FAIL`，即告警也没发出去）。这是「重启风暴」的最小可复现形态。

**修法（watchd）**：
- 停滞判据改**多源** `last_progress_ts` = max(browse_log 末条, state.json 内容/mtime, level_log mtime, daemon 启动时刻) ⇒ 段间长休、静默窗、刚起队都不再算停滞；
- 加**冷启动宽限**（daemon 起队后 N 分钟内不判停滞）；
- 新增 `BLOCKED_ENV`：判定「环境不可用」（无 linux.do 会话 / 前台被占 / CF 挑战）时**只记事件不重启**——环境问题重启无用，只会把节律打碎；
- `RESTART_MIN_GAP` 冷却与 `FAIL_STREAK_NOTIFY` 保留（今日 76 次 `RESTART_SKIP=COOLDOWN` 即冷却在工作）。

## 3. 缺陷③：长休未接线（「五动作共用同一随机内核」是文档承诺）

**症状（R545）**：daemon 里有第二份节奏常量（`GAP_LONG_RANGE`/`GAP_LONG_P`），只在自测里被断言 ⇒ **死常量**；内核 `day_segments()` 在 daemon 里零调用，长休（段满 110min 才休）实际从未发生。

**修法**：daemon 的 `_batch_gap()` 改走内核 `gap_seconds()`、当日段表改走内核 `day_segments(day,'browse')`（§1），本地常量删除；自测新增断言「生产路径确实调到内核」（不再只看常量存在）。

## 4. 缺陷④：level_log.jsonl 被节流行污染

**症状**：等级检查的**节流分支**（每 301s 命中一次）也写 `level_log.jsonl` 并把 `st["level"].ts` 刷成当前时刻 ⇒ 台账里节流记录混入，无法据此判断「上次真检查是何时」（R545 §④「检查频次不可取证」）。

**修法**：节流分支**只打日志**，不写台账、不刷 `level.ts`；只有真检查（带 `source`）才落 `level_log.jsonl`。自测新增负控：模拟节流轮次后断言台账行数与 `level.ts` 均不前进。

SOP 里内嵌的「工具真跑输出」会随实现漂移：本批把 `memory/linuxdo_acts_sop.md` §八 的 daemon `28/28`→`32/32`、watchd `25/25`→`52 checks`，并在 §九（看门狗三件事第②条）改写停滞判据为多源 + BLOCKED_ENV 语义、§十 新增三条历史坑（段计时进程内 = 重启重排 / 自测里的常量不算「单一源」 / 台账被高频分支污染）。**铁律：改判定逻辑必须同批回填文档里的自证数字**（同 herdr-agents 的 gate_claim_replay 口径）。
