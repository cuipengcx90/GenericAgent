## 4. 口径与坑（本轮实际踩到）

1. **`du -d` 在本机不可用**：`du -sk -d 1 <dir>` → `rc=64 usage:`（三种写法均试）。替代：glob 展平 `du -skx path/* path/.[!.]*`。
2. **du 总量 > df used**：`du -skx /System/Volumes/Data` = 440 264 445 KB（419.9 GiB）> df used 409.13 GiB。原因=**APFS 克隆被重复计**：如 `~/Documents/chatlog/.../message_0.db` 1 027 MB 与微信容器内同库 1 027 MB 同源（不同 mtime）。⇒ 顶层归因表相加会略高于 df，**这是正常口径差，不代表有隐藏占用**。
3. **稀疏文件**：OrbStack `data.img.raw` 逻辑 460.43 GiB / 实占 14.01 GiB ⇒ 大文件清单必须用 `st_blocks`（`du`）而非 `st_size`，否则误报 460 GiB。
4. **容器目录 TCC**：`~/Library/Containers/**` 递归 `find` 会被 TCC 挂起 ⇒ 只用 `du`/`ls` 限深 + 显式超时（本轮 `du` 走 TCC 可读路径正常返回）。
5. **后台起任务失败静默**：两次 `nohup bash -c '...' >log` 起的长任务产出 0 字节日志（进程已退），改用**前台 + 显式 timeout** 才拿到结果 ⇒ 判"后台在跑"必须回查日志非空，不能只看 `ps`。
6. **失败重试纪律**：`du -d` 失败 3 次后即改写法（glob），未在原地重试。
