## §3 打分口径（确定性、可复算、可争辩）

```
priority = 2×影响面(0-5) + 2×阻塞度(0-3) + 可逆性(0-3) − 2×风险惩罚(0-2) + 积压加成(0-2)
```

* **影响面**：≥1GB 级回收 +2；100MB 级 +1；出现 3–99 的「N 个文件/任务/报告」+1；
  命中系统级词（memory/L1/L2/L3/launchd/定时/全局）+1；命中回收类词（回收/释放/瘦身）+1；封顶 5。
  * 注：>99 的数字**不计**入多变更（实测台账里有「knowledgeC 17400 对象」这类**数据条数**，
    若当变更规模会把纯统计句误读成「要改 1.7 万处」）。
* **阻塞度**：命中「阻塞/卡住/前置/依赖/否则/必须/才能/无法/死锁/等用户」等词各计 1，封顶 3。
* **可逆性**：回滚列非空，或文本含 回滚/备份/copytruncate/stash/dry-run ⇒ 3；
  含不可逆词（删除/覆盖/清空/迁移/rm）且无回滚 ⇒ 1；其余 ⇒ 2。
* **风险惩罚**：含不可逆动作 ⇒ 2；含风险词 ⇒ 1。
* **积压加成**：来源日距今 ≥1 天 +1，≥3 天 +2（封顶 2）。
* **并列次序**：`(-priority, -积压, ID, 文件)`，全程确定性（同输入两次运行逐字节相同，§5 D）。
* **类别**：8 条关键词规则把条目归入 记忆/文档、磁盘/回收、定时/调度、通知/推送、工具/脚本、数据/取证、其他。

## §6 已知边界与残余风险（不夸大）

1. **打分是启发式，不是事实**：完全由台账文本里的关键词/数字正则推出 ⇒ 一条写得含糊的条目会被低估。
   `--top` 的分是**排序建议**，不是批准依据；每条的实际内容仍需人读（工具输出里带一句话摘要 + 批准入口）。
2. **同分档内排序无信息量**：38 条同为 8 分，名次由 ID 字典序决定（已在输出里显式声明）。
3. **工具在 `temp/` 内（gitignored）**：本轮**未**落 `tools/` ⇒ 不构成本仓耐久资产；
   是否生产化属待批（§7-①）。
4. **未接入任何自动推送/定时**：`--top` 只能手动跑或由未来任务调用；本轮未新增任何定时器。
5. **类别规则可能误判**：例：一条提到「飞书」的磁盘清理条目会先命中 记忆/文档 之外的第一条规则；
   规则按固定顺序匹配（先匹配先算），已在源码里标注可调整位置。
