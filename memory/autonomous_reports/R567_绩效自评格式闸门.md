交付后自检发现工具**声明的退出码契约无效**,当场修并加负控:

- **真缺陷 1:`SystemExit("rc=2 …")` 字符串负载 ⇒ 实际退出码恒为 1**。Python 对非 int 的 SystemExit 负载一律 `exit(1)`(负载只打到 stderr),故「2=输入或环境错误」的声明静默失效;`check` 与 `selftest` 的缺依赖路径都中招。
- **真缺陷 2:`cmd_selftest` 裸 `import openpyxl`**,在无 openpyxl 的解释器(本机 `/usr/bin/python3`)下裸 traceback + rc=1,与 `load_wb` 的守卫行为不一致。
- **修法**:新增 `_require_openpyxl()` ⇒ 缺依赖统一 `raise SystemExit(2)`;`cmd_selftest` 改走该守卫;全部退出点只传 **int**。
- **负控强化**:NC13 改为**真退出码**判定(subprocess 跑缺文件路径,断言 rc==2);新增 NC14(模拟缺依赖 ⇒ 必 rc=2、禁 rc=1);新增 NC15(用 AST 断言源码里所有 `SystemExit` 的负载均为 int **常量**,不看 docstring 文本——初版按文本匹配曾误报一轮)。
- **验证**:`/opt/anaconda3/bin/python3 … selftest` = **16/16 passed** rc=0;`/usr/bin/python3 … selftest` ⇒ 干净报 `rc=2 缺 openpyxl(用 /opt/anaconda3/bin/python3 跑)`(不再裸 traceback rc=1);真身表 `check` 仍 `PASS` rc=0、`proof` `unchanged=True`。
- **开发坑(差点二次踩)**:判据正则字符类里 ASCII `;` 与全角 `;`(U+FF1B)**同形难辨**,源码里一律写 `\uFF1B` 转义;曾因替换丢失一次导致 T1 正控与 I7/I8 全量假 FAIL。
- **文档同批回填**:SOP 闸门段 selftest 计数 14→16 + 退出码语义铁律(缺依赖也归 rc=2、禁字符串负载);本报告 §1/§3 计数同步订正为 16。
