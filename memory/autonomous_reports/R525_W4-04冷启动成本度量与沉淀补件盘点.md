## 2. 口径（三句话，取自 F17 §1）

- **能力面** = `control-plane/*/`，**排除**本器自身输入/输出面（`coldstart_v0/` 基线落点、`consumer_replay_v0/` 登记面、`l1_map_v0/` 索引面）——把输入/输出当被测量会造成自指假红。
- **成本** = 必读面三份（入口脚本 + `README.md` + 规格）字节/行数之和；`ramp_bytes` = 规格里**第一个围栏代码块之前**的字节数；分档 `LOW` < 8 KiB ≤ `MID` < 32 KiB ≤ `HIGH`。
- **沉淀五件套**（每件都是「文件存在 ∧ 可机械判定」）：`entry`（含 `__main__`/`main(` 的非 test 脚本）、`readme`、`spec`（`docs/product/*.md` 中**逐字**出现 `control-plane/<id>/`）、`tests`（`test_*.py`）、`index`（`l1_map_v0/index.json` 有条目）。

**闸门分两级**：硬问题 `UNDECLARED`（未登记在 dispositions.json）/ `COST_REGRESSION`（相对基线涨幅超 `--tol`，默认 15%）⇒ rc=1；建议项 `MISSING_SEDIMENT`（已登记能力缺件）默认 rc=0，`--strict` 才升级。理由：存量缺件是**度量结果**不是故障，默认判红则本仓恒红 ⇒ 哨兵失效。

## 4. 根因修复：census 把本器误判成「别家能力的生产消费者」

- **症状**：glob 化之前，全仓 `run_tests` 唯一红 = `consumer_replay_v0` 的 `test_real_repo_gate_rc0`（census rc≠0）。
- **根因**：`coldstart.py` 里**字面写死**了 `consumer_replay_v0/dispositions.json` 与 `l1_map_v0/index.json` 两处输入面路径 ⇒ census 的 token 抽取把本器算作这两家能力的**生产消费者**（`prod`），而它们在 `dispositions.json` 里声明为 `DOC_ONLY` ⇒ `MISMATCH` + `CATEGORY_VERDICT_CONFLICT`（verdict 被翻转）。
- **修法**：改为按**文件名 glob 动态发现**输入面（与 R522 `console_v0` 同一条口径：写死子系统名会让 census 把本文件算作答家的生产消费者并翻转其 verdict）；同时抹掉自注释/docstring 里残留的字面 token。
- **验收**：census `rc=0 / declared=27 / problems=0`；本器 selftest 65/65、pytest 24 passed 零回归。
