## 一、结论

4. **§4 表列的 100 条强断言断链里 29 条落在 `temp/` 易失区（下表 ○ 标记）。** temp 是 gitignored 运行区，产物被清理属常态（R375 已实证）；真正需要人看的是非 temp 路径的断链（● 标记）。本报告把两者在表里标出，避免把"临时文件被清"误读成"报告撒谎"。

## 二、口径与可复跑

**工具**：`tools/report_assert_audit.py`（新增，只读）。它 `import tools/memory_assert_audit` 复用 R378 核验器的常量表、basename 索引与分类口径（F1/F2/F4/F5、kind 全集），只把其中"解析报告正文"的一段重写为函数。

**语料**：
- 被审对象（报告正文）：`memory/autonomous_reports/R*.md` + `temp/R*.md`（未归档草稿）。
- 引用语料（判断"谁引用了这个路径"）：`memory/*.md|txt`、`memory/*/*.md|txt`、`temp/TODO.txt`、`sche_tasks/*.json`、`reflect_scripts/*.py`、`tools/*.py`。

**判据**（与 R378 同源，逐条对齐）：
- 路径 token 抽取 → kind 分类（EXT/TMP/ABS/HOME/UP/REPO/BARE）→ 存在性判定（BARE 走 basename 索引）→ 上下文分类（F1 已归档/已删、F2 待批/计划、F4 举例/占位、F5 其它）→ PASS / FAIL / AMBIG。
- **强/弱分级（本工具新增）**：strong = 有目录或根前缀的路径（TMP/ABS/HOME/UP/REPO），或 BARE 但其所在行含"产出/产物/新增/落盘/生成/建立…"等自称产物语境的 claim；weak = 裸文件名且行内无该语境（多为代码碎片）。
- **引用计数（本工具新增）**：统计每个断链目标被多少份**其它**文档的正文/台账引用过（`ref_n_other`，剔除断链所在报告自身的引用），排序键 = (-他引, -总引, -claim, -新)。

**复跑命令**（cwd = 仓库根；★交付口径的 JSON 必须用「不带 `--negctl`」的干净跑产出，负控另起一跑，否则合成报告会混进统计——本工具首版就栽过这一次，已修）：
```bash
python3 tools/report_assert_audit.py --top 300 --json temp/report_assert_audit.json > temp/rpt_full.log 2>&1      # 干净交付跑
python3 tools/report_assert_audit.py --top 300 --negctl --json temp/rpt_negctl.json > temp/rpt_negctl.log 2>&1   # 负控跑（只取 NEGCTL 行）
python3 tools/report_assert_audit.py --no-index --last 5 --negctl      # 秒级冒烟，含负控
```

**负控（工具自检，防"校验器全绿但其实没读到语料"）**：内存合成一份报告 + 一份合成记忆，四项判据必须全过。原始输出：
```text
NEGCTL {"fake_referenced_flagged": true, "fake_referenced_has_refs": true, "fake_referenced_before_unreferenced": true, "real_file_passes": true}
```
四项判据 = ①被引用的假断链必须被标 FAIL 且进 ranked；②未被引用的假断链必须排在它后面（证明排序真的在用引用数）；③被引用假断链的 `refs_other ≥ 1`；④真存在于磁盘的路径必须 PASS（防"全判 FAIL"的假绿）。

**只读证据**：工具内置 sha1 前后比对，对报告语料的写入违规数为 `write_violations=[]`（空 = 零写入）。

**零写入**：工具只 `open(..., 'r')` 报告与引用语料，唯一写出物是 `--json` 指定的结果文件与 stdout；对报告语料的 sha1 前后比对违规数 = `[]`。本次运行未执行任何 `git add/commit`、未修改任何报告或记忆文件。
