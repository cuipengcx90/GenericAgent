## 6. 为什么对这台机器有用

1. **暴露消费面缺口**：这些域名有访问行为、零文字记录 ⇒ 说明「访问」与「沉淀」之间存在系统性漏记录（多数来源是 SOP 里没写的资源站与工具文档站）。
2. **给采集类任务提供候选源**：A 节（AI 中转/公益站）可直接喂 `fofa_cli_proxy_hunter_sop` 的候选 base URL；B 节（网盘/IT 资源站）是 `birdiesearch_monitor_sop` 的加源候选。
3. **可复算**：重跑 `scan` 即可看清单变化，无需人工维护域名表——但需先有新的冻结副本（Default 走 R415 每日快照，非 Default 需另行冻结，见 §8.4）。

## 8. 局限（不可越界解读）

1. **域名级零提及 ≠ 项目级零提及**：末列可见 herdr 501 / tutti 18 / trytrellis 4 次，说明这些项目本身进过报告（裸词口径另计：herdr 501 / tutti 18 / trellis 134 / orca 29，`onorca` 作为站点标签 0 次 ⇒ 读末列须注意「标签写法」差异），**只是从没记录过这些域名**。
2. **「零提及」只对 memory 与 temp/autonomous_reports 两类语料成立**：sche_tasks / tools / logs 等未纳入判定面 ⇒ 本报告不能断言某域名全机零提及。
3. **末列计数口径**：按 base 首段做子串计数（`trytrellis` 可命中 `docs.trytrellis.app`；但 `api`/`www`/`www2` 这类公共首段会大量误命中）⇒ 仅作「项目名是否出现过」的下界参考。末列计数文件集比工具语料更宽（含工具按扩展名/体积排除的文件），仅供参照。
4. **数值绑 2026-09-27 快照，数据源是两份节奏不同的冻结副本**：web 主体＝R415 每日快照 `temp/chrome_snapshots/2026-09-25/History`（Default profile），另加 R437 于 09-26 冻结的 9 个非 Default 副本 `temp/chrome_profiles/2026-09-26/*/History` ⇒ 复算须重跑第 0 节命令，勿引用本文旧数。
5. **K=100 时零提及为 0** ⇒ 结论只在 K=20/50 档成立。
