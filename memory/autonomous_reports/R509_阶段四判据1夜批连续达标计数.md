## 3. 三档口径（逐层加严）

| `--profile` | 一夜算「达标」的条件 | 用途 |
|---|---|---|
| `ledger` | `intervened == False` | 与 `report` 的按夜率同源，可对账 |
| `device` | 再加 `forced == 0` | 装置自己撑不住（被迫叫人/降级）也不算达标 |
| `strict` | 再加 真实 run 数 ≥ `--min-real-runs`（默认 2）且墙钟 ≥ `--min-wall-s`（默认 0.5 s） | 排除「2 个 run 0.02 秒跑完」的演练型夜（`DRILL_LIKE`） |

退出码：`0` 判据达标 / `1` 判据**未达标**（审计结论，非执行失败）/ `2` 台账读不出来。

★ 口径要点：`verdict` 判的是**窗口率**（`--window N` 夜内达标率 ≥ `--min-rate` 即 `MET`），
而判据原文「连续 7 天」是**链长口径** ⇒ 两者会不一致（见 §4 的 `device`），故两处文档都已写明
「别只看 `verdict` 那一行」。
