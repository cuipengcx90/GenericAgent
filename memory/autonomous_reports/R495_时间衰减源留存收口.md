## 3. 留存窗口实测（walk 源内容 time token，不依赖快照目录）

`rolling_source_coverage.py window` 原始输出（存档 `temp/source_retention/r495/window.txt`）：

```
─ chrome   快照 3 份 最新=2026-09-29  数据窗 2026-06-30 → 2026-09-28 (91 天)  距窗口起点滚出 0 天  [chrome.visits_range]
─ kc       快照 4 份 最新=2026-09-29  数据窗 2026-09-02 → 2026-09-29 (28 天)  距窗口起点滚出 0 天  [kc.app_usage_range]
─ pmset    快照 2 份 最新=2026-09-29  数据窗 2026-09-15 → 2026-09-29 (15 天)  距窗口起点滚出 0 天  [pmset.asl_filenames]
─ wifilog  快照 2 份 最新=2026-09-29  数据窗 2026-09-29 → 2026-09-29 (1 天)  距窗口起点滚出 1 天  [wifilog.day_tokens]
```

要点：
- **wifilog 窗口 1 天**（`newsyslog` 每日 00:30 轮转）⇒ 漏采一天即永久丢失，是全链路唯一的硬约束源。
- chrome 探针 `oldest_available=null`（源库热态 `database is locked`，只读探针不可得）⇒ 该源只有**声明留存**可用，属已声明边界，不得写成「实测 90 天」。
- `days_left` 优先取探针实测（`days_left_src=probe`），探针不可用时退回声明值并标 `src=declared`；探针窗超出声明留存时按声明留存收紧（负控 T30/T31 锁此行为，去掉收紧即复现 636 天式假乐观）。

## 4. 账本（append-only）与复核

落账命令 `claim --apply` ⇒ `temp/source_retention/coverage.jsonl` 8 条声明：chrome 2 / kc 4 / pmset 2 日 **COVERED**（数据在更晚快照内）+ wifilog 2026-09-27 / 09-28 **UNCOVERED**。
幂等实测：同批重跑 ⇒ `appended 0 / skipped 8`。
`audit` 原始输出（`temp/source_retention/r495/audit.txt`）：

```
■ 账本复核（8 条声明；今天=2026-09-29）
─ 摘要: 仍成立 8 / 失效 0  rc=0
```

每条声明带可复算证据（`artifact` 路径 + `artifact_sha256_16` + `min_day/max_day/n/rows_on_day`）；**证据失效即 rc≠0**，账本不会「永远绿」。

`salvage --apply`：只对 `UNCOVERED` 且仍在源窗内的日尝试补采。wifilog 这两日返回 `UNSUPPORTED`（单日轮转后无任何更晚快照含该日数据）⇒ 判**真丢失**，**不生成占位文件**（伪造一天数据比缺一天更坏）。

`proof`：只读自证，快照树 61 文件 sha256 前后一致（prompt 层面「未改源库」）。
