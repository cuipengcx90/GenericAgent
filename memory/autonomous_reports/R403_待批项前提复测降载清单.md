台账里其余条目的「前提」是**散文**（如「草案已备」），机器不可判；本报告**不把它们当可复测前提**（否则就是猜）。

### 1.2 前提定义（按 kind 写死）

| kind | 前提（P） | 复测观测量 |
|---|---|---|
| `create` | P1 目标文件**不存在** | `os.path.exists(tgt)`；若存在则再比内容是否一致 |
| `insert` | P1 锚点**恰好命中 1 次**；P2 目标内容未含待插入块 | `text.count(anchor)`；`content in text` |
| `replace` | 同 `insert` | 同上 |
| `append` | P1 目标文件存在；P2 追加内容未含 | `os.path.exists`；`content in text` |
| `copy` | P1 源文件存在；P2 目标 sha256 ≠ 源 sha256 | `os.path.exists(src)`；`sha256(src)==sha256(tgt)` |
| `manual` | 无机器可判前提 | — |

### 1.3 判定矩阵（verdict）

| verdict | 含义 | 归入清单 |
|---|---|---|
| `ACTIVE` | 前提仍成立 | **仍需拍板** |
| `ALREADY_DONE` | 目标已含目标内容（已完成） | **建议关闭** |
| `STALE` | 前提消失（锚点 0 命中 / 源缺 / 目标缺） | **建议关闭（需重写或放弃）** |
| `REWRITE` | 锚点歧义(>1) 或目标已被占（`create` 目标存在但内容不同） | **需重写声明 / 人工判断** |
| `NO_PREMISE` | `manual` | 需人看（不可机器降载） |

## 7. 边界与不可比口径

- 本报告只测**前提是否成立**，**不测**条目是否「值得做」；即使前提成立，用户仍可决定不做（则按「放弃」关闭）。
- 前提会随上游编辑漂移：`insert/replace` 的前提是**当时**锚点唯一，任何对目标文件的编辑都可能使其失效（C11 即此例）。⇒ 建议：**凡机器声明的前提，执行前先跑一次 `premise_recheck.py`**，避免 `apply.py` 报 FAIL 才发现。
- 未覆盖：其余 90 条未决只有散文前提，本工具**判定不到**（这是设计边界，不是缺陷）。
- 复测时刻：2026-09-25（前提状态随源码/记忆编辑漂移，数值不作永久结论）。
